# 改动：管理端「案例管理」按设计稿改版

日期：2026-11-07

## 结构

从「左列表 + 右详情分栏」改为：

```
案例列表（整宽一张卡）
  ├─ 标题「案例列表 · 共 N 个案例」
  ├─ 筛选：搜索姓名/编号 + 案例状态
  ├─ 表格：姓名/案例编号 · 所属院系 · 关注等级 · 案例状态 · 筛查次数 · 最近筛查 · 操作
  └─ 分页：共 N 条 · 第 X 页 + 页码 + 上/下一页

点「查看详情」/ 点行 → 右侧滑出 660px 抽屉（遮罩、Esc、点遮罩、× 均可关）
  ├─ 头部：案例详情 / 查看案例资料与筛查记录
  ├─ 资料：姓名 + 关注等级 + 案例状态、案例编号、
  │        年龄 / 性别 / 所属院系 / 标签、累计筛查次数 / 最近筛查
  ├─ 页签：筛查记录（20）| 跟进记录（预警 + 时间线）
  │   ├─ 筛查记录：表格（筛查时间 / 量表·得分 / 查看）+ 前端分页（每页 5 条）
  │   │            点「查看」弹出该次筛查的小结（日期 / 量表 / 得分）
  │   └─ 跟进记录：预警历史、案例维护（状态 / 备注 / 保存）、
  │                新增跟进、案例时间线
  └─ 底部：关闭详情
```

## 说明

- 设计稿里资料区的「年级」在现有数据模型里没有独立字段（`department` 里带着“大三”），
  所以第 4 格用的是「标签」；院系照原样显示（如“外国语学院 大三”）。
- 以前固定右栏的「不点就不知道右边有内容」问题，现在由**显式的「查看详情」按钮 +
  抽屉**解决：列表是主角，详情是点开才出现的次要层。
- 保留原有全部功能与接口：`GET /api/admin/cases`（分页筛选）、`GET/PUT /api/admin/cases/{id}`、
  `POST /api/admin/cases/{id}/timeline`；保存/新增跟进后列表与详情一起刷新。
- 抽屉打开时锁住页面滚动；Esc 先关筛查小结弹窗，再关抽屉。
- `components/MasterDetail.tsx` 不再被本页使用（预警中心/预警管理仍在用）。

## 验证

- 连真实后端（adminer / admin）：列表 1 条案例、抽屉 20 条筛查分 4 页、跟进记录 69 条（预警 + 时间线）。
- 交互：行点击与「查看详情」都能开抽屉；点「查看」开小结；Esc 逐层关闭；未选中时无抽屉。
- `tsc -b`、`eslint`、`vite build` 通过；浏览器 console 无报错。
