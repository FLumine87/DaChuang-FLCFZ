# 个人复查与站内通知：本轮交付说明

本轮只打通一条业务流程：工作人员发送复查 → 个人确认并完成问卷 → 工作人员查看结果并记录复核。代码在 `codex/personal-review-notifications-20261106`，基于 PR #4 的 `codex/admin-workflow-20261106`，交队长审阅合并，没有部署线上网站。

## 可以怎么展示给队长看

1. 管理端进入 Agent 工作台，切换真实业务空间。对关联了个人账号的案例，将一项任务“确认并分配”。未审核草案、演示空间或无账号案例不能发出真实复查。
2. 进入该案例详情，在“复查发送与反馈”选这项任务。填写个人可见的标题、说明、量表、计划日期，预览接收人及内容，再确认发送。预览时取消不会发送。
3. 用该个人账号登录，在顶部通知铃铛或“我的复查任务”找到任务。确认收到只记录收件状态，不算完成；点击“开始复查”作答并提交。
4. 返回管理端案例详情，点击“刷新复查状态”，或等待约30秒/重新聚焦页面，看见量表得分及待复核状态。工作人员填写内部处理记录，确认保存后变为已复核。
5. 个人收到通用的已查看通知，可以查看自己的筛查记录。管理端内部任务标题、操作备注和复核记录不会下发给个人。

状态为：待确认 → 已确认收到 → 已提交，待复核 → 已复核。个人也可直接开始作答。提交前工作人员可以取消，取消后拒绝作答提交；不会自动完成原 Agent 任务或关闭预警，原有专业人员审批仍独立保留。

## 本轮实现边界

- 通知是站内消息，页面打开后约每30秒检查并支持标记已读；不包含短信、邮件、微信、系统推送、定时逾期催办。
- 每个已审核 Agent 任务只创建一次复查。重复点击或网络重试不重复建任务、筛查、预警或通知。要发起下一次复查，应先建立新的跟进任务。
- PHQ-9、GAD-7、ISI、PSS-10 复用既有前端问卷，服务端按现有计分规则复算答案，不接受前端伪造分数。既有高分预警流程继续保留，问卷结果不自动成为诊断。
- 当前沿用项目已有 admin/user 权限；咨询师在现有系统中使用管理端角色，尚未增加按咨询师分组的数据权限。
- 本轮未加入 Agent 的文字变化摘要、增强跟进草案，也未把复查待复核数量新增到今日工作统计；待复核通过站内通知和案例详情查看。

## 代码与接口

- `backend/app/services/review_service.py`：发送、本人读取与提交、复核、取消、通知及可见字段白名单。
- `backend/app/db/database.py`：SQLite 事务 / D1 batch，结果、状态、预警及通知一起提交或回滚。D1 batch 用法参照 [Cloudflare 官方文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。
- `frontend/src/admin/components/CaseReviews.tsx`：工作人员发送预览、反馈列表、内部处理。
- `frontend/src/pages/ReviewTasks.tsx`：个人收件箱、确认收到、完成问卷。
- `frontend/src/components/NotificationBell.tsx`：两端站内通知，优先列未读消息，避免旧未读消息被100条列表限制遮住。

新增 API：

| 方法与路径 | 用途 |
| --- | --- |
| POST /api/admin/reviews | 发送已审核任务的复查 |
| GET /api/admin/reviews?case=CASE-xxx | 案例复查及结果、内部记录 |
| PUT /api/admin/reviews/{id} | 带版本号复核或取消 |
| GET /api/personal/reviews | 本人任务 |
| POST /api/personal/reviews/{id}/acknowledge | 确认收到 |
| POST /api/personal/reviews/{id}/submit | 提交原始答案 |
| GET /api/notifications | 本人通知及未读数 |
| PUT /api/notifications/{id}/read | 标记本人通知已读 |
