# 改动：管理端「预警管理」列表分页 + 右侧详情与左列等高

日期：2026-11-07

## 需求

1. 右侧详情框要拉得和左侧列表一样长（未选中时的空态不能比列表矮一截）；
2. 左侧分页，每页 4 条，别再拉成一条很长的滚动列表；
3. 整块尽量在一屏内铺满。

## 改动

### 后端：`GET /api/admin/alerts` 支持 `page_size`

`backend/app/handlers/admin.py`

- 新增 `page_size` 查询参数（1–100，默认 50），`LIMIT/OFFSET` 与返回的 `pageSize` 都按它走。
- 默认值保持 50，其它调用方不受影响。

### 前端

`frontend/src/services/adminApi.ts`
- `listAdminAlerts` 接受 `pageSize`，mock 模式按同样大小切片。

`frontend/src/admin/pages/AdminAlerts.tsx`
- 每页 4 条（`PAGE_SIZE = 4`），底部分页改为「上一页 + 页码 + 下一页」（共 24 条 → 6 页）。
- 筛选条不再单独套一张卡（原来那张卡把列表推到首屏外），改成一条紧凑输入行；
  卡片内边距、描述行数同时收紧，去掉列表内部滚动。
- 使用 `MasterDetail matchList`：**行高只由左列决定**，右侧详情/空态撑满同一高度
  （详情内容更长时在面板内部滚动，不会再把左侧拉高）。

`frontend/src/components/MasterDetail.tsx`
- 新增 `matchList`：详情容器在 ≥lg 时绝对定位，不参与行高计算，再 `inset-0` 撑满左列高度；
  手机上仍是正常堆叠。
- `DetailPanel` 新增 `embedded`：撑满容器、内部滚动，不再 sticky。
- 空态增加 `flex-1`，在拉高后的面板里垂直居中。

## 结果

- 1270×825 下：筛选行 + 4 张预警卡 + 页码分页 + 等高详情全部在首屏内，
  分页按钮底部 823px（视口 825px）；右侧空态与左列同为 576px 高、内容居中。
- 详情内容较长时（处理人、备注、处理历史）在右栏内部滚动，左列不会跟着被撑高。
- 移动端（390px）仍是单列：列表 → 分页 → 详情。

验证：`tsc -b` / `eslint` / `vite build` 通过；接口 `page_size=4` 返回 4 条、`pageSize: 4`；
浏览器 console 无报错。截图：`.shots/alerts-paging/`。
