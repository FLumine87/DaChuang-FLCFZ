## 三、并入的三种做法（推荐 A）

### 方案 A：合并 main，然后逐处解冲突（推荐）

```bash
git checkout feature/frontend-redesign
git merge old-origin/main
```

- **冲突已预演过：8 处**（`git merge-tree` 实测）
  - 内容冲突：`App.tsx`、`AdminLayout.tsx`、`AdminAlerts.tsx`、`AdminCases.tsx`、`AdminDashboard.tsx`、`Layout.tsx`、`QuestionnaireForm.tsx`（还有 `Screening.tsx`/`http.ts` 视情况）
  - modify/delete：`AdminAgentWorkbench.tsx`（他们删了，我们改过）
- **解冲突的统一原则**：
  1. **保留我们的视觉与结构**（AppShell / 令牌 / 首次引导那套），
  2. **保留他们的功能接线**（新页面、`services/*.ts`、路由与导航项、`AdminAgentWorkbench → AgentWorkspaceV2` 的替换、量表回写逻辑），
  3. 拿不准的以"功能不丢"为先，样式后面再统一。
- 优点：一次到位，之后不用反复对齐；缺点：8 处冲突集中解，约 2–4 小时

### 方案 B：不合并，按功能"移植"

只挑要的功能：`git checkout old-origin/main -- frontend/src/pages/me frontend/src/services/{api,adminApi,workspaceApi}.ts frontend/src/admin/pages/AgentWorkspaceV2.tsx`，然后自己接路由、自己套样式。
- 优点：不碰我们的现有文件，风险最小
- 缺点：他们的 `App.tsx`/`AdminLayout` 改动要手工重做一遍；后续 main 再更新还会重复这件事

### 方案 C：先只接后端，前端功能押后

先把 `backend`/`personal-backend` 的新代码合进来（这部分我们没动过，几乎无冲突），前端等答辩主线（首次引导 + 改版）稳定后再接。
- 适合"答辩前时间紧、只想保证现有流程好看好用"的情况

### 7.3 接了哪些端点、实测返回

新增 `frontend/src/services/firstRunRetrieval.ts`：先探 `GET /api/v1/health` 定三态，`live` 时并行调 inference 与 extract。

| 端点 | 实测返回（本机，Neo4j 未启动） |
| --- | --- |
| `GET /api/v1/health` | `200 {"status":"ok","neo4j_connected":false,"mock_mode":false}` |
| `POST /api/v1/inference/run` | `503 {"detail":"Neo4j 未连接，无法执行推理"}` |
| `POST /api/v1/kg/extract` | `502`（真实 LLM key 是占位符，认证失败） |
| `GET /api/v1/kg/graph/{user}` | `503 {"detail":"Neo4j 未连接，请先启动 Neo4j 并配置 .env"}` |
| `GET /api/v1/checkin/daily` | `200 {"user_id":"xiaoyu","message":"今天过得怎么样？有什么想聊的吗？😊","neo4j_connected":false}` |
| `GET /api/v1/recommendations/by_interest` | `200 []` |

界面按这些**如实**展示，四种状态都有话说：

- `unreachable`（health 都失败）→「这一版尚未参与本次结果…」（沿用原措辞）
- `mock`（`mock_mode=true`）→「当前为演示模式：后端未接入真实检索…」，**不调**真实接口
- `live` 有数据 → `matched_disorders` 列表化（名称/匹配症状/匹配诱因/相似度/覆盖率，最多 5 条 +「其余 N 条略」）；RAG 用 `report.factors` 与 `recommendations[].reason`
- `live` 出错 → 「检索服务暂不可用」。**注意：出错与"无命中"是互斥渲染的** —— 服务都没答上来就不能再说一句"本次未检索到"，那等于替失败的检索下结论
- 知识关联 → 仅在有补充文字时出现，展示 `kg/extract` 的三元组，并如实说明是否写入图谱

字段映射的坦白说明：后端**没有** `sources`/`references` 这类字段，所以 RAG 那条没有伪造文献列表，
用的是 schema 里本来就写着"来自领域 KG"的 `factors` 与 `recommendations[].reason`；
"相似线索"用的是 `matched_disorders`（后端侧唯一的结构化命中结果）。接口没给的字段一律不显示。

### 7.4 后端怎么起的

**两个后端 + 一个代理规则**（这是本次踩到最大的坑）：

- 主 `backend/`（管理端 `/api/admin/*`、`/api/agent-workspace`）默认 **8000**，`DATABASE_URL=sqlite:///./data/dev.db`（不需要 Postgres）。
  仓库里没有可用的 venv（`backend/.venv` 是从别人机器拷来的，`pyvenv.cfg` 指向 `/Users/zhengjie/...` 且没装依赖），
  需 `python3 -m venv venv && ./venv/bin/pip install -r requirements.txt`（含 numpy/Pillow）。
- `personal-backend/`（个人端 `/api/v1/*`）默认 **8001**，走它自带的 `venv` + `requirements.txt`。
- **两边都占 `/api`，以前会互相抢 8000**：`vite.config.ts` 原先只有一条 `/api → 8000`，
  所以 personal-backend 无论跑哪个端口，前端都够不着它。
  现在加了一条更具体的规则（更具体的键在前）：
  `/api/v1 → personal-backend(8001)`、`/api → 主 backend(8000)`，两个服务可以同时跑。
  可用 `VITE_PERSONAL_PROXY_TARGET` 覆盖。
- 同时把 `services/api.ts` 的基地址从写死的 `http://localhost:8001` 改为
  `VITE_API_BASE → VITE_API_BASE_URL → ''`（同源相对路径），这样 `.env.local` 里的代理配置才真正生效；
  原先写死端口会让代理完全失效，而且 `localhost` 与 `127.0.0.1` 在浏览器里还是不同源。

`personal-backend/.env` 从 `.env.example` 复制而来（已被 `.gitignore` 忽略，不会提交）。
其中 `LLM_API_KEY=sk-your-key` 是占位符 —— 这会让 `/kg/extract` 真的去请求 DeepSeek 并拿到 401，
所以它实测是 502 而不是走 mock 抽取器。要看 mock 抽取效果应显式设 `ENABLE_MOCK_ENGINES=True`。

### 7.5 视觉令牌化做了什么

- `admin/pages/agent-workspace.css`：**整份重写**为 `var(--color-*)`，硬编码色值为零。
  顶部 `--ink/--muted/--line/--blue` 保留原名但改为指向令牌（下游几十处不用动）；

  一个坑：主按钮文字**必须**用字面 `white`，不能用 `--color-white` ——
  后者在本仓库是"表面色"令牌，深色下会重映射成 `#151d2c`，拿它当按钮文字色就是深底深字
  （`index.css` 的 `.ui-button-primary` 同样写 `white`）。
- `AgentWorkspaceV2.tsx`：去掉页内重复渲染的 `h2` 与面包屑（AppShell 已输出眉标/标题/说明/面包屑），

- `pages/me/KgPage.tsx`：节点与分类配色原是硬编码十六进制，而 **SVG 的 `fill`/`stroke` 不解析 `var()`**。
  改为运行时 `getComputedStyle` 读令牌 + `MutationObserver` 监听 `html.dark`，主题一换色板跟着重算。
- 顺手修掉两个自查发现的显示缺陷：错误态与"无命中"原先同时渲染；错误短句叠字。

`rememberSubmittedRecord` 保留 —— 自己刚提交的筛查仍要出现在列表与档案里。

修掉的真 bug（都不是环境问题）：

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 打开工作台 V2 就被强制登出 | `http.ts` 的 401 拦截器无条件 `clearToken()` + 跳登录页；演示登录发的是 `alg:none` 的自家 token，真实 backend 校签必拒 | 新增 `isDemoToken()`：演示 token 的 401 只透传给调用方（页面显示"无效或已过期的凭证"），不清凭证不跳转；真实 JWT 的 401 仍按原逻辑登出 |
| 03 页摘要与展开自相矛盾 | 摘要按"行数为 0"就写"本次未检索到"，而展开分支已按"出错优先"渲染 —— 等于替一次失败的检索下了结论 | 摘要与展开用同一套优先级：有数据 → 出错 → 无命中 → 未接入 |
| 错误短句叠字 | `briefError` 归一后的文案与标签相同仍拼括号 | 相同时不再重复 |
| 检索条目"出错"与"无命中"同时渲染 | 两个独立条件分支 | 改为互斥 |
