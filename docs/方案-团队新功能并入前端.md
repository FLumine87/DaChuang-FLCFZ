## 三、并入的三种做法（推荐 A）

### 方案 A：合并 main，然后逐处解冲突（推荐）

```bash
git checkout feature/frontend-redesign
git merge old-origin/main
```

- **冲突已预演过：8 处**（`git merge-tree` 实测）
  - 内容冲突：`App.tsx`、`AdminLayout.tsx`、`AdminAlerts.tsx`、`AdminCases.tsx`、`AdminDashboard.tsx`、`Layout.tsx`、`QuestionnaireForm.tsx`（还有 `Screening.tsx`/`http.ts` 视情况）
  - modify/delete：`AdminAgentWorkbench.tsx`（他们删了，我们改过）
- **解冲突的统一原则**：
  1. **保留我们的视觉与结构**（AppShell / 令牌 / 首次引导那套），
  2. **保留他们的功能接线**（新页面、`services/*.ts`、路由与导航项、`AdminAgentWorkbench → AgentWorkspaceV2` 的替换、量表回写逻辑），
  3. 拿不准的以"功能不丢"为先，样式后面再统一。
- 优点：一次到位，之后不用反复对齐；缺点：8 处冲突集中解，约 2–4 小时

### 方案 B：不合并，按功能"移植"

只挑要的功能：`git checkout old-origin/main -- frontend/src/pages/me frontend/src/services/{api,adminApi,workspaceApi}.ts frontend/src/admin/pages/AgentWorkspaceV2.tsx`，然后自己接路由、自己套样式。
- 优点：不碰我们的现有文件，风险最小
- 缺点：他们的 `App.tsx`/`AdminLayout` 改动要手工重做一遍；后续 main 再更新还会重复这件事

### 方案 C：先只接后端，前端功能押后

先把 `backend`/`personal-backend` 的新代码合进来（这部分我们没动过，几乎无冲突），前端等答辩主线（首次引导 + 改版）稳定后再接。
- 适合"答辩前时间紧、只想保证现有流程好看好用"的情况

## 四、并进来之后，前端要做的适配（按文件）

| 文件 | 要做什么 |
| --- | --- |
| `App.tsx` | 合并路由：保留我们的 4 条首次引导路由，接入他们的 `/personal/me/*`（三页）与管理端工作台 V2 路由 |
| `components/AppShell.tsx` | 侧栏是数据驱动的 `items` 数组，加"智能体 / 知识图谱"导航项即可；管理员端把"预警处置工作台"指向 V2 |
| `admin/pages/AdminAgentWorkbench.tsx` | 按他们的做法**删除**，改指向 `AgentWorkspaceV2.tsx`；V2 的样式（`agent-workspace.css`）需要按我们的令牌（颜色/圆角/投影）过一遍 |
| `pages/me/ChatPage|FeedPage|KgPage` | 套我们的外壳与卡片样式；数据层直接用他们的 `services/api.ts` |
| `services/http.ts` | 我们加过 `getTokenUsername()`，他们改过 token 相关逻辑 —— 合并时两处都要留 |
| `components/QuestionnaireForm.tsx` | 他们的"量表回写"改动与我们首次引导向导都会写筛查记录，合并后要确认**只写一次**、不被向导流程重复提交 |
| `package.json` | 接 Playwright 依赖（他们加的 e2e），与我们的 `.tools/qa/*.mjs`（CDP 走查）并存，互不影响 |

## 五、验证顺序（合并后照这个跑）

1. `cd frontend && npx tsc -b && npx eslint src && npm run build`
2. `node .tools/qa/first-run.mjs`（我们的首次引导 55 项）
3. `node .tools/qa/walk.mjs`（工作台回归 21 项，含新增的 Agent 页面路径要补进去）
4. 他们的 `npx playwright test`（要先起后端；`scope=demo` 若能离线跑就更省事）
5. 起 `backend` + `personal-backend`，人工点一遍：个人端 Agent 对话/知识图谱、管理端工作台 V2
