# 检索到筛查的闭环改动

> 检索页主路径已按后续反馈改为直接汇总本次多模态命中生成初筛结论，不再依赖补充问答或量表。当前实现见[检索结果直接初筛](改动-检索结果直接初筛-2026-11-07.md)。下文保留早期改动背景，量表规则仍用于独立量表页面。

日期：2026-11-07。范围：检索页面的实际用途展示，以及本次讨论清单中的 1、2、6、8、11、12。

## 现在的使用流程

1. 个人端“检索与分析”输入近况，或上传媒体线索。检索结果先返回。
2. 本次输入保存后，页面上方显示“本次筛查结论”：本人依据、信息缺口、检索用途、下一步。
3. 基础规则询问尚缺的持续时间、频率、生活影响。匹配睡眠或兴趣维度的检索参考，会实际选择对应的具体表现追问；未采用的参考标为候选。
4. 本人回答保存到同一补充记录，直接更新初步分析，不要求填写量表。量表入口默认折叠；如用户自愿选择，可携原补充ID和新筛查ID返回，补充同一份分析。
5. 需要复核时生成预警，并提供预警入口。采用依据中可查看“参考单元→追问→本人回答→统一规则”的过程。
6. 本人的历史记录可恢复保存的评估；可主动关联或解除量表。新查询不复用旧补充ID，同一输入切换检索范围不重复保存或丢失追问。

“开心”直接输出当前积极表达的线索结论，并说明不能据此判断整体心理健康；不会要求量表才能结束检索。困扰线索可独立输出初步关注建议，持续且频繁的本人困扰、明显功能影响或安全线索可直接建议复核。补充近况也是可选操作，信息局限如实展示。取消保存时只作预览，不累计负面情绪记录。

## 判断和标签

- 风险与复核建议由 `backend/app/services/screening_assessment.py` 统一生成。相似度、命中数量和参考样本风险颜色不直接给用户定级。
- CSEMOTIONS/FER的单次情绪或表情标签对应筛查状态未知。EATD标签明确为SDS自评筛查来源；SDS阳性不等于确诊或当前危机。
- 旧语料在读取时规范化标签，不要求重建大语料库。外部弱配对图片不会继承文音被试的SDS标签，也不会继承另一模态的“已采用”用途。
- 本人已保存文本中，近14天至少3个不同自然日有负面情绪表达，触发橙色“高风险关注（待复核）”。同日重复、外部命中、明确否定和明确谈论他人不计入。此为项目关注规则，尚无临床效度验证，不作为疾病诊断或自伤概率。
- 上述窗口与阈值可在启动后端的进程环境变量中设置：`SCREENING_NEGATIVE_WINDOW_DAYS`、`SCREENING_NEGATIVE_DAY_THRESHOLD`，默认14和3；不是新增的`.env`配置项。
- 量表症状程度、复核优先级和安全线索分别保留。明显功能影响、量表与本人描述的矛盾可触发复核；不相关的低分量表不代表当前困扰评估完成。
- PHQ-9安全相关作答独立复核，不被低总分覆盖。既往或不明确的安全表达进入澄清复核，不直接当作当前紧急情况。

## 量表版本和技术来源

- 统一版本：`2026-11-standard-v1`；前端上传原始选项序号，`answerEncoding=option-index`；后端重新计分。
- PHQ-9、GAD-7、ISI使用各自的症状分段。PSS-10校正题序，仅4、5、7、8反向，保留0–40分，不设置统一临床诊断或危机分界。
- 旧PSS记录不按新题序自动重解。新记录返回原始作答、版本和编码方式，逐题页面区分选项与分值。
- PSS来源：[Cohen实验室评分说明](https://www.cmu.edu/dietrich/psychology/stress-immunity-disease-lab/scales/html/pssscoring.html)；[量表使用说明](https://www.cmu.edu/dietrich/psychology/stress-immunity-disease-lab/scales/index.html)。量表分段参考：[AHRQ筛查工具表](https://www.ncbi.nlm.nih.gov/sites/books/NBK592808/table/ch1.tab5/)。
- 首次流程中，真实哈希结果来自主后端；`matched_disorders`明确作为个人知识图谱参考。图谱参考分不再自行覆盖筛查等级或新建风险预警。
- 保存补充、同步量表、抽取信息完成后再运行依赖这些信息的推理；前置失败时如实提示，不使用旧信息冒充本次结果。
- RAG使用同一份后端评估。模型可以组织说明，不能覆盖后端摘要、风险和下一步建议；未完成量表不编造0分。

## 主要接口与存储

`POST /api/personal/retrieval-assessment`：接收本人查询、可选的`screeningId`、`supplementId`和`followupAnswers`，返回`assessment`。`screeningId:""`表示主动解除当前补充的量表关联。

补充、追问、采用引用、规则版本与评估存入既有`screening_supplements.analysis`；校验当前用户归属。预览不持久化，回答追问前须有本人已保存记录。现有表结构可复用，无新增业务数据库迁移。

## 验证与边界

- 主后端新增无量表独立分析、无量表复核和不强制自测的回归；个人图谱后端保留原有3项参考来源回归。
- 浏览器回归：13项通过，覆盖检索结论、追问保存、同记录量表返回、历史恢复、主动解除关联、新旧查询隔离、保存完成后的评估时序、首次流程来源与PSS计分。包括“开心”后的自愿自测入口保留原记录。
- TypeScript、生产构建、定向ESLint及`git diff --check`。
- 浏览器测试拦截业务API，使用合成数据；主后端流程测试使用临时/内存数据库。没有通过测试改写现有业务DB或重训真实模型。
- 本次不宣称已验证筛查准确率；自由文本线索仍是可解释的词典与规则原型，图像/声学情绪不自动视为已确认本人症状。临床验证和更深的跨模态语义训练不属于本次改动。
- 本次仅完成本地代码与构建，未发布线上服务。Cloudflare构建从`backend/app`打包wheel，未手工覆盖生成的`worker/python_modules`依赖副本。
