## 三、B 类 · 空实现 / 占位（6 项）

> 这类最危险：**接口存在、前端有界面，但返回空数据或硬编码**，演示时容易被当场发现。

### B-5 文件上传接口

- **项目书承诺**（4.4.3 数据采集模块 + 4.5 节）：支持文本/语音/图像上传，**分片直传对象存储**，触发特征提取任务。
- **核查结果**：`app/handlers/upload.py` 第 19 行直接
  `raise HttpError(503, "文件上传功能暂未启用（R2 存储未激活 / multipart 解析待实现）")`。
- **注**：检索页的图像/语音查询走 base64 内联，**不经过此接口**，故检索功能不受影响；
  受影响的是"数据采集页面的上传"。

### B-6 对象存储（R2）

- **核查结果**：`backend/worker/wrangler.toml` 中 `[[r2_buckets]]` **被注释**，
  注明 R2 未激活（code 10042）。
- **恢复方式**：Cloudflare Dashboard 激活 R2 → 取消注释 → `npx wrangler r2 bucket create mental-screening-uploads`。

### B-7 管理端采集数据查询

- **项目书承诺**（4.4.5 节）：管理端可查询个人用户数据。
- **核查结果**：`app/handlers/admin.py` 的 `get_admin_data_collection` **直接返回三个空数组**
  `{"textSubmissions": [], "audioSubmissions": [], "imageSubmissions": []}`。
- **影响**：管理端"数据采集"页面为空页。

### B-8 用户个人资料字段

- **项目书承诺**（4.4.1 节报告页 + 个人档案）：展示筛查对象、所属信息等。
- **核查结果**：`app/handlers/personal.py` 第 140、173 行，

  "stage": "", "emergencyContact": ""}`，仅从 `screenings[0]` 回填 `name` / `gender`。
- **根因**：`users` 表无对应字段（见 G-32）。

### B-9 报告页维度评估与作答详情

- **项目书承诺**（4.4.1 节）：维度评估模块通过雷达图呈现情绪低落、焦虑紧张、睡眠问题等维度。

### B-10 后端量 tables 无种子数据

## 四、C 类 · 项目书承诺的架构组件缺失（5 项）

> 项目书 4.4.5 节"数据存储层"与"五、辅助机制"明确列出的组件。

### C-11 向量数据库（Milvus）

- **项目书承诺**（4.4.5 节 + 4.5 节）："存储多模态特征的二进制哈希码及对应元数据 ID，
  支持**亿级规模**的汉明距离检索"，流程中明确写"写入向量数据库 Milvus"。
- **核查结果**：检索 `milvus|faiss|pgvector|vector_db` → **0 命中**。
  `wrangler.toml:37-39` 有 Vectorize 的**注释掉的预留配置**，DEVELOP.md 明确记为"本期不做"。
- **现状替代**：多哈希表索引在应用内存中构建（`multi_table_index.py`），
  状态持久化到本地 JSON；**Worker 环境下真实引擎已降级为 Mock**。

### C-12 缓存层

- **项目书承诺**（4.4.5 节）："存放热点数据，如高频检索结果、会话令牌等以加速响应"。
- **核查结果**：无独立缓存组件（无 Redis / KV / Memcache）。
  代码中的"缓存"均为**应用内局部变量**（如 `engine.py:77` 缩略图缓存、
  `engines/__init__.py:36` 引擎单例），非架构级缓存层。

### C-13 消息队列

- **项目书承诺**（五、辅助机制 + 4.5 节）："用于异步任务解耦，
  例如文件上传后触发特征提取与哈希索引，避免阻塞主流程"。
- **核查结果**：检索 `celery|rabbitmq|kafka|message_queue|消息队列` → **0 命中**。
- **影响**：特征提取与哈希索引均为**同步调用**，无异步解耦。

### C-14 SSE 流式传输

- **项目书承诺**（五、辅助机制 + 4.5 节）："在 RAG 报告生成过程中，**逐字推送**内容至前端，降低用户等待焦虑"。
- **核查结果**：`deepseek_rag_engine.py:202,238` 两处均为 `"stream": False`；
  前端检索 `EventSource|text/event-stream` → 0 命中。
- **影响**：报告**一次性返回**，无流式展示。

### C-15 Kubernetes 容器化部署

- **项目书承诺**（五、辅助机制）："Docker 与 Kubernetes 的容器化部署：
  所有服务打包为容器，支持弹性伸缩与 **GPU 资源调度**"。
- **核查结果**：存在 `backend/Dockerfile`、`frontend/Dockerfile`、`db_tools/Dockerfile`、
  `docker-compose.yml`（Docker 部分已落地）；**无任何 K8s 配置**（无 k8s / kube 相关文件）。
- **注**：生产环境已改为 Cloudflare Workers serverless 架构，
  Docker 链路为本地开发用途，K8s 与 GPU 调度与本项目实际部署形态不符。

## 五、D 类 · 算法承诺未落地（5 项）

### D-16 Hadamard 矩阵正交优化

- **项目书承诺**（3.1 节）："利用 Hadamard 矩阵正交特性优化各模态哈希表学习，
  保证哈希码的语义一致性"。
- **核查结果**：检索 `hadamard` → **0 命中**。

### D-17 BSPLH 半监督哈希

- **项目书承诺**（4.7.1 节）："针对单个哈希系统训练，本项目拟采用半监督哈希算法

### D-19 交叉熵 + 余弦距离双指标权重

## 八、G 类 · 数据层地基缺失（2 项）

> 这两项不在项目书承诺清单里，但**阻塞了多个已承诺功能**，属隐性地基问题。

### G-31 `screenings` 表缺 `user_id`

- **证据**：`DEVELOP.md` 2026-09-22 条目明确记录："仍待办：`screenings` 表缺 `user_id`，
  学生端检索尚未做归属作用域过滤（需与账号模块对齐后实现）"。
- **实际影响**：`personal.py` 所有查询均为**无用户限定的全表查询**，例如
  `SELECT * FROM screenings ORDER BY screening_date DESC, id DESC LIMIT 100`
  —— **任何登录用户都能看到全部筛查记录**，这是数据越权。
- **阻塞**：个人端"我的档案"、个人预警、个人检索的归属过滤全部依赖此字段。

### G-32 `users` 表缺 profile 字段

- **证据**：`app/db/database.py` 的 `SCHEMA_SQL` 中，`users` 表**无**
  `campus` / `major` / `stage` / `emergency_contact` 字段。
- **实际影响**：直接导致 B-8（个人资料字段全为空串）。
- **阻塞**："完善用户个人资料部分"这一任务**在数据层没有基础**，无法实现。
