## 一、共性：三套"左列表 + 右详情"互不一致

| 页面 | 未选中时 | 加载时 | 滚动时详情 | 默认选中 |
|---|---|---|---|---|
| 个人端·预警中心 `pages/Alerts.tsx` | 提示文案**垂直居中**，卡片被左列表拉高 → 落在首屏外，看起来是空白 | 无 | 随页面滚走 | 否 |
| 管理端·预警管理 `admin/pages/AdminAlerts.tsx` | 图标 + 标题 + 两行说明，`min-h-[460px]` 居中 | 居中"正在加载详情…" | 随页面滚走 | 否 |
| 管理端·案例管理 `admin/pages/AdminCases.tsx` | 一行字，卡片 `h-fit`（很小） | "返回列表"+ "正在加载详情…" 两行 | 随页面滚走 | 否 |

三处的共同缺口：

1. **没有默认选中**——首屏右半边天然是空的，评委会以为"这页没做完"。
2. **没有 sticky**——列表一长，详情栏早滚出视口，点卡片后看不到变化。
3. **空态不像"可操作"**——个人端那块尤其像 bug（见第 5 条）。
4. **加载态像空白**——案例管理把"返回列表"和"正在加载详情…"同时显示（`AdminCases.tsx:174-176`），
   既像已经进详情、又什么都没有，正是"我以为是弹窗"的观感来源。

**建议先抽一个 `<MasterDetail>`（列表 + 详情栏）**，统一四件事：`sticky top-16`、
空态（图标 + 一句话 + 一句说明）、骨架加载、未选中时是否默认选第一条。三处替换后
5、9 两条的大部分工作量就消化掉了。

## 二、逐条

### 4. 左下角这个方框没有意义；头像/账号入口应该在左下

**截图**：侧栏底部一张浅色卡——盾牌图标 + "每一份关注，都有意义" + "从了解自己开始，照顾好每一天。"，
下面一行 "心理健康 · 个人健康空间"。

**现状（代码）**

- 这张卡是纯装饰：`AppShell.tsx:460-472` 里没有任何 `onClick` / `Link`，只有图标和两句文案。
- 账号入口只有右上角：`AppShell.tsx:625-688`（头像 + 用户名 + 下拉：我的档案 / 退出登录）。
- 文案与登录页重复：卡上的副标题与 `pages/LoginPage.tsx:251` 的
  "从了解自己开始，照顾好每一天。" 一字不差；"个人健康空间" 又在下拉菜单 `:662` 出现一次。
  也就是说这块地方**没有提供任何新信息，也不承担任何操作**。
- 侧栏收起时整张卡消失：卡上带 `sidebar-label`，而 `index.css:429-431` 对 `.sidebar-label`
  是 `display:none`，于是折叠态左下角只剩一句版权字（`AppShell.tsx:473-493`）。

**为什么被提**：侧栏左下角是"账号/身份"的黄金位置（Slack、Linear、Notion 都在这里），
现在放了一句口号，用户既找不到"账户"，也读不出这张卡的用途。

**改法 A（推荐）：卡片 → 账号卡**

```
┌──────────────────────────────┐
│  (张)  张三              ⌃   │  ← 头像（首字母/渐变底）+ 显示名
│        个人健康空间 · 用户    │  ← 身份/空间，一行小字
└──────────────────────────────┘
                 ↓ 点击（向上弹出，portal）
        ┌──────────────────┐
        │ 我的档案          │
        │ 账户与安全（占位） │
        │ 深色模式   [开关] │
        │ 退出登录          │
        └──────────────────┘
```

- 头像：会话里只有 `username`、`role`（`auth/session.ts`），没有头像 URL，沿用右上角
  "首字母圆形头像"的做法即可，不必等后端。
- 菜单向上弹：现有下拉是 `useAnchorRect` + `createPortal` 的向下定位（`AppShell.tsx:83-106,646-687`），
  加一个 `placement: 'up'` 参数复用即可，注意 `mask-image` 的裁剪问题已经由 portal 解决。
- 顺带收口：右上角头像在桌面端可以去掉（只留主题切换），避免两个账号入口；
  移动端侧栏是抽屉，账号卡在抽屉底部反而更好按。
- 折叠态：卡里只留头像（去掉 `sidebar-label`，或用 `data-collapsed` 单独样式），不要整块消失。

**改法 B（若想保留这句话）**：把卡片做成"有信息的状态卡"，例如
"最近一次筛查 · 10-30 · 关注 / 去查看"，口号降级为卡片顶部的小字。
好处是保住了情感化表达，坏处是它仍然不是账号入口，还得另找地方放头像——不如 A 干净。

**要拍板的一件事**：这里的"进入账户"是
①只开一个菜单（推荐，零新增页面）；
②还是要一个真正的账户页（资料 / 隐私 / 数据导出 / 注销）？
目前产品里没有账户页，`我的档案`（`pages/Cases.tsx`，含姓名/性别/年龄/阶段/专业）最接近"个人资料"。
若选②，路由建议 `/personal/account`，档案页继续管筛查记录。

**验收**：左下角可点头像进菜单；折叠态仍可见头像；右上角不再出现第二个账号入口；
登录页口号与侧栏无重复文案。

### 5. 预警中心：不点案例，没人知道右边会显示文字

**截图**：左侧三条预警，右侧一块从上贯到下的大白卡，**里面什么都没有**；
点过之后（第二张图）右侧才出现 ALT-8D89FF 的详情。

**现状（代码）**

- 外层三列网格：`Alerts.tsx:118` —— `grid grid-cols-1 lg:grid-cols-3 gap-6`。
- 详情栏：`Alerts.tsx:164` —— `ui-card flex flex-col p-5`。网格默认 `align-items: stretch`，
  右边这张卡被左列（2/3 宽、三条预警）**拉到同样高**。
- 空态：`Alerts.tsx:228-232` —— `flex flex-1 flex-col items-center justify-center py-8`，
  文案"选择一条预警查看详情"被**垂直居中**在很高的卡片里，实际落在首屏之外。
  截图里那块"空白"就是它。
- `selectedAlert` 初值是 `null`（`Alerts.tsx:11`），所以首屏必然是这个状态。

**为什么被提**：这是"空态位置错误"，不是"没有空态"。用户看到的是空白 → 以为右侧没内容。

**改法（三步，可只做前两步）**

1. **空态上移**：`justify-center` → `justify-start pt-10`，或给卡片 `min-h` 并让网格
   `items-start`（`Alerts.tsx:118` 加 `items-start`），高度不再被左列拉满。
2. **默认选中第一条**：`useState<string|null>(null)` → 在数据到达后
   `setSelectedAlert(list[0]?.id ?? null)`。右侧首屏就有内容，且"点卡片 → 右侧变化"这一关系
   自然被看见；这也是邮箱/工单类界面的通行做法。
3. **详情栏 sticky**：`lg:sticky lg:top-[80px] lg:max-h-[calc(100vh-96px)] lg:overflow-auto`，
   列表再长也不会点完看不到。
4. （可选）移动端：`grid-cols-1` 时详情卡排在列表下面，点完要滚很久——改成点开后在
   该条卡片下方内联展开，或用一个底部抽屉。

**顺手统一**：管理端预警页已经有一版更好的空态（`admin/pages/AdminAlerts.tsx:159-183`：
`MousePointerClick` 图标 + 标题 + 说明 + 空态/加载态互斥），个人端直接复用同一段，
不要两边各写一份。

**验收**：首次进页面右上就有内容或明确提示；点任意一条，右侧内容在视口内可见；
页面滚到底部时详情仍可见。

### 6. 管理端：多模态采集和检索与分析是同一件事，却隔得很远

**截图**：侧栏是「多模态采集 / 数据审核 / 案例管理」→ 分组「智能分析」→「检索与分析」。

**现状（代码）**

- 「多模态采集」在**工作空间**组：`AppShell.tsx:156-161`。
- 「检索与分析」在**智能分析**组：`AppShell.tsx:193-199`。
- 两者之间还隔着「案例管理」（`:229-239`）和一个分组标题（`:423` 的四个分组名）。
- 但路由是紧挨着的：`App.tsx:143-144`（`data-collection` 与 `retrieval` 相邻）——
  代码里它们是一对，导航里却像两个不相干的模块。
- 内容上确实是同一条链路：采集页按**文本 / 语音 / 图像**三个页签审阅提交
  （`admin/pages/AdminDataCollection.tsx:467-470`），检索页也是按**文本 / 图像 / 语音**
  发起查询并出 RAG 报告（`admin/pages/AdminRetrieval.tsx:27,89-138`）。
  同一条模态轴、同一批数据，一个负责"入库/审阅"，一个负责"出库/分析"。

**为什么被提**：评审看到两个页面都在处理"文本/语音/图像"，却分属两个分组，
会认为要么功能重复、要么关系不清。

**改法（按成本从低到高）**

1. **导航重排（先做，10 行以内）**：把「检索与分析」移到工作空间、紧跟「多模态采集」；
   或者新开一组「多模态数据」＝采集 / 检索与分析（将来再加数据审核）。
   智能分析组只留研判台、处置工作台，语义反而更清楚。
2. **页内互跳（半天，和 1 一起做）**：
   - 采集页顶部与检索页顶部共用一组分段控件「采集 | 检索」；
   - 采集详情里加「检索相似案例」→ 跳 `/admin/retrieval?q=<该条摘要>`；
   - 检索结果里加「查看来源采集」→ 跳回 `/admin/data-collection`。
   这样"同一件事"是被**用**出来的，而不只是摆在一起。
3. **合并成一个模块（1–2 天，可后置）**：`/admin/multimodal?tab=collect|search`，
   共用筛选栏与语料上下文，旧路径做 redirect。收益是信息架构彻底干净，
   代价是牵动 e2e、文档和书签，且短期内页面会变大。

**建议**：这一轮做 1+2，3 留到功能稳定后再评估。

**验收**：从任一页到另一页 ≤1 次点击、0 次跨分组；两页顶部能看出"采集→检索"的先后关系。

### 7. 管理端：图像查询和拍照查询合成一个按钮（和个人端一样）

**截图**：一排按钮——图像查询 / 拍照查询 / 语音查询 / 检索。

**现状（代码）**

- 两个独立按钮：`admin/pages/AdminRetrieval.tsx:104-127`。
  - 「图像查询」→ 触发隐藏的 `input[type=file]`（`:90-96`）；
  - 「拍照查询」→ 打开 `CameraCapture`（`:117,293-297`）。
- **小 bug**：两个按钮的选中态都用 `modality === 'image'` 判断（`:108-111` 与 `:120-123`），
  于是选完图后**两个按钮同时高亮**，看起来像两个都"开着"。
- 个人端已经是对的：一个图片图标按钮 + 下拉「从文件选择 / 现场拍照」
  （`pages/Retrieval.tsx:463-502`），语音也是同样的「从文件选择 / 直接录音」（`:418-462`）。

**改法**

1. 管理端把两个按钮合成一个：「图像查询 ▾」，点开两项——「从文件选择」「现场拍照」。
   交互直接照搬个人端那段（含点外部关闭的透明遮罩 `Retrieval.tsx:477`）。
2. 建议顺手把这套下拉抽成 `components/MediaQueryMenu.tsx`（图标 + 两个动作 + 当前模态高亮），
   个人端与管理端共用，避免以后两边再分叉。
3. 语音同理：「语音查询」→「上传音频 / 直接录音」（个人端已有录音器 `hooks/useAudioRecorder`）。
4. 选中态改为单一来源：显示"当前是图像查询 + 文件名"的 chip（`:149-171` 已有），
   按钮本身只表示"打开菜单"，不表示模态。

**验收**：工具栏少一个按钮；选完图只有一个高亮/一个 chip；拍照与选文件走同一条 `pickMedia` 链路
（现有实现已满足，别改坏）。

### 9. 案例管理：不点就不知道右边会冒信息，还以为是弹窗

**截图**：左边一张案例卡（只占了左半列），右边一张小卡写着"← 返回列表 / 正在加载详情…"，
中间一大片空白。

**现状（代码）**

- 左右分栏：`AdminCases.tsx:140` —— `lg:grid-cols-[minmax(0,2fr)_minmax(300px,1fr)]`。
- 案例卡网格：`AdminCases.tsx:145` —— `sm:grid-cols-2`。**只有 1 条数据时，卡片只占左列的一半**，
  另一半空着（截图正是这个状态）；再往右才是详情栏，中间形成一块约 500px 的空白。
- 详情栏：`AdminCases.tsx:172` —— `h-fit`，未选中时只有一行灰字（`:173`），
  选中后出现"返回列表"+ 加载文案（`:174-176`）。
- 详情**不是弹窗**，是同一页右侧的面板；但"返回列表"这种按钮语义、以及点卡片后
  右上方孤零零冒出一张卡，都容易被读成"弹了个窗"。

**为什么被提**：三件事叠一起——①列表卡没有"可点/可查看"的暗示；②详情出现在远处；
③1 条数据时布局本身是坏的（半宽卡 + 大空白）。

**改法（二选一，建议 A）**

**A. 保留主从布局，但把它做成"真·分栏"**

- 列表改整宽单列（或 `auto-fill minmax(280px,1fr)`），不再用 `2fr/1fr` 让卡片只占半格；
- 详情栏 `lg:sticky lg:top-[80px]`，未选中时给图标 + "选择一个案例查看详情"+ 一句说明
  （照抄 `AdminAlerts.tsx:163-176` 那版）；
- 卡片加"查看详情 →"或在 hover/选中时显示指示；选中态已有 `ring-2`（`:148-149`），可再加强；
- 去掉详情里的"返回列表"（分栏里换一张卡就是返回），改成标题栏右侧 `×` 清空选中；
- 加载态改骨架屏，不要"返回列表 + 正在加载详情…"两行并排。

**B. 改成右侧抽屉（slide-over）**

- 列表整宽；点卡片从右滑出 480–560px 抽屉（遮罩、Esc 关闭、移动端全屏），
  详情内容不用重排（现在那段 `<aside>` 直接搬进抽屉即可）；
- 更符合"点一下看详情"的心智，也顺手解决"详情在右边看不出来"；
- 代价：抽屉里要处理滚动与焦点陷阱，工作量比 A 大半天。

**C.（不推荐）真弹窗**：字段太多（筛查记录/预警历史/维护表单/跟进/时间线），
弹窗会很挤，且与预警页的处理方式不一致。

**验收**：1 条数据时页面不出现"半张卡 + 大空白"；未选中时右侧有明确指引；
选中后详情在视口内；列表滚动时详情不消失。

## 三、建议批次

| 批次 | 内容 | 说明 |
|---|---|---|
| 第 1 批（半天） | #7 合并按钮；#5 空态上移 + 默认选中 + sticky | 改动小、评审核价最高 |
| 第 2 批（1 天） | 抽 `<MasterDetail>`，替换 #5 / #9 / 管理端预警 | 一次收口，避免继续分叉 |
