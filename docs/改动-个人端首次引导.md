# 改动：个人端首次登录引导（欢迎页）

> 缘起：2026-10-13「只在个人用户第一次登录时展示一次，做一张简洁的欢迎页，
> 而不是直接把问卷弹出来」。视觉按当轮定稿的样张实现，文案沿用样张。
> 本轮同时要求：文字与图形分级渐入、适配浅色深色两种模式。

## 一、需求落点

| 需求 | 实现 |
| --- | --- |
| 只在**个人账号第一次登录**时出现一次 | 登录成功后判断账号的引导状态，首次才跳 `/personal/welcome`；管理员端没有这个流程 |
| 不直接把问卷弹到脸上 | 欢迎页先讲清楚"做什么、要多久、结果去哪"，再让用户选方向 |
| 从情绪 / 焦虑 / 睡眠 / 压力里**挑一个**，不必四份都做 | 四张卡对应仓库里已有的 PHQ-9 / GAD-7 / ISI / PSS-10 |
| 提交后**先看本次结果**，再进主页 | 三步向导：01 逐题作答 → 02 补充记录（可选）→ 03 本次结果 →「进入个人主页」 |
| 「先进入主页」直接进主页 | 记下"看过引导"，跳 `/personal/dashboard` |
| 跳过的人首页显示"还没有筛查记录" + 一个随时可用的入口 | 首页英雄卡的空状态：入口是「开始首次筛查」（回欢迎页挑方向） |
| 开始后中途退出，下次直接进主页并提示"继续筛查" | 状态留在 `in_progress`，首页入口变成「继续筛查」，直接回到 01 那份量表 |
| **记的是账号是否看过引导，不是有没有记录** | 见下面的状态机；判据与记录数量完全解耦 |
| 正式使用时状态应存在账号上，跨设备生效 | 读写集中在 `readState`/`writeState` 两个函数，换成后端接口即可（见第四节） |
| 量表介绍要讲"这是什么"，不是操作教程 | 「了解 XX」弹窗按图六重写：量表介绍 → 名称 → 简介 → 这份量表关注什么（四组图标）→ 它如何帮助你 → 结果的边界 →「返回当前题」 |
| 答题页自带"怎么答"和"结果怎么用" | 进度条下一条低对比度说明条（回想的时间范围 / 选项按什么选，按量表切换）+ 选项下一行结果用途提示 |
| PHQ-9 第 9 题要就地给支持信息 | 该题左栏出现「需要支持时」支持卡（可展开具体求助方式），不挤占选项、不改变答题卡尺寸 |
| 长题目不要断在词中间 | 题干用**自然折行**（`text-wrap: normal`，见 `.first-run-question`），禁用 balance/pretty；答题卡宽度全程不变 |

## 二、状态机

```
new ──点「开始首次筛查」──▶ in_progress ──提交成功──▶ done
 │                              ▲
 └──点「先进入主页」────────────┘（留在 new）
```

| 状态 | 含义 | 下次登录 | 首页英雄卡 |
| --- | --- | --- | --- |
| `new` + 未看过 | 全新账号 | 进欢迎页 | （还没进来过，看不到） |
| `new` + 已看过 | 跳过引导：**没有记录，但处理过引导** | 直接进主页 | 「还没有筛查记录」+ 开始首次筛查 |
| `in_progress` | 选了量表但没提交（中途退出） | 直接进主页 | 「还没有筛查记录 · 上次选的方向还没做完」+ 继续筛查 |
| `done` | 完成过一次 | 直接进主页 | 正常首页 |

两个刻意选择：
- **点过按钮才算"看过"**：只把欢迎页打开又关掉标签页的，下次还会看到——因为用户其实没做选择。
- **登录页只跳转、不拦截路由**：`/personal/*` 的深链（收藏、刷新、从预警邮件进来）一律照旧，
  不会被弹回欢迎页。这也让既有的 `.tools/qa/walk.mjs` 走查保持原样。

## 三、四屏流程（步骤统一为四步）

```
/personal/welcome            欢迎页（选方向 / 先进入主页）
      │  开始首次筛查
      ▼
/personal/first/questionnaire?scale=PHQ-9     01 逐题作答
      │  提交并查看结果（这里落 recordId 与分数）
      ▼
/personal/first/supplement                    02 补充记录（可选：文字 / 语音 / 图片）
      │  提交补充并查看结果 ／ 跳过补充，查看量表结果
      ▼
/personal/first/result                        03 本次结果 + 结论来自哪里
      │  进入个人主页 ／ 查看完整分析
      ▼
/personal/dashboard
```

**步骤编号统一成四步**：`选择方向 → 回答问题 → 补充记录（可选） → 查看结果`。
02 补充记录本身就是一个独立页面，若左栏还按三步画，就会出现"顶部写 2/3、
左栏却高亮第三步"两套编号打架；现在顶部（首次筛查 · n/4）与左栏步骤由同一份
定义生成（`firstRunSteps.ts`），状态提示也紧挨步骤名称放，不再甩到最右侧。
欢迎页是第 1 步（顶栏显示「首次使用」），所以向导三屏是 2/4、3/4、4/4。

四屏共用一个外壳 `pages/first/FirstRunShell.tsx`（顶栏「首次筛查 · n/3」+ 左栏叙事 +
三圈同心轨道背景 + `.welcome-in` 分级渐入），所以换步骤时视觉是连续的。
01 与 02 之间、02 与 03 之间用 `sessionStorage` 里的**草稿**（`startDraft` / `saveDraft` /
`getDraft`）传量表、分数与补充内容——不放进 URL：分数和补充内容不该出现在地址栏里，
而且用户在 02 按 F5 也不该被打回第一步。

### 02 补充记录：技术说明贴着操作出现

原来的问题是两段技术介绍独立摆在左下角——那里是展示流程的位置，又和右边的填写操作
没有联系。现在左栏只放 标题 + 一句说明 + 步骤条；右侧卡片的顺序固定为
「想补充些什么？→ 文字/语音/图片切换 → 输入区 → 报告生成方式 → 提交/跳过」。
技术说明条是一行低调的小字 + 小图标 + 淡边框：

```
报告生成方式   ⌘ 动态跨模态哈希检索 → ▤ RAG 检索增强生成  (i)
```

技术名称直接可见（评委在填写时就看得到两个创新点），点 (i) 才展开那一句解释，
默认不铺开大段说明。

### 03 本次结果：合成一张「本次筛查报告卡」

原来是"得分卡 + 结论来自哪里 + 下一步"三块横着摆，得分最小、依据占最大面积、
按钮又单独一块。现在右侧是**一张卡**，从上到下：顶部（本次筛查结果 + 量表名/完成时间）
→ 核心结果（得分，切标签时始终可见）→ 三个标签（结果摘要 / 分析依据 / 后续建议）
→ 底部操作按钮（只留「进入个人主页」）。左栏约占 35%、右侧报告约占 65%，左栏与右卡顶部对齐。

三个标签分别放什么：
- **结果摘要**（默认）：一段结果解释 + 必要的量表说明；得分已在上方，不重复；
  首次没有历史数据，不画趋势、不提"比上次改善"。
- **分析依据**：三条可展开条目——本次作答与补充（量表、补充了什么）、动态跨模态哈希检索、
  RAG 参考资料。后两条标注「了解分析技术」，展开后明确写"这一版尚未参与本次结果"，
  不把技术介绍冒充成本次结论的证据。
- **后续建议**：两条，短标题 + 一句说明，相关操作跟在旁边。

**PSS-10 单独处理**：PSS 作者实验室明确说明它不是诊断工具、没有统一的分数截断值，
所以 PSS-10 不走临床分级——不写"中度压力"、不配四色风险条，只写
「本次压力感受记录 / 得分 / 量表范围 0–40」，配一条 0–40 的简单刻度标明得分位置，
并注明"这条刻度只表示在量表区间里的位置，不是百分比"；摘要里也写明
"上面的分组是系统参考分组，不是临床结论"。PHQ-9 / GAD-7 / ISI 有通行的严重程度
分档，仍显示分档条。

### 入场动效

按「背景先亮、文字后到」的顺序分级（实测透明度曲线）：

```
同心圆轨道/柔光(0ms) → 眉标(80) → 标题(170) → 正文(260) → 要点(350)
→ 卡片(760ms 时长) → 四张量表卡(560/630/700/770)
```

只动 `opacity / transform / scale`（合成层属性，不触发重排重绘）。
轨道那三圈用的是**独立的 `scale` 属性**而不是 `transform`——登录页用 Tailwind 的
`scale-[1.35]` 画另外两圈，那条工具类写的是 `transform`，两者相乘，因此动画不会把圆的尺寸顶掉。

### 演示数据为什么要按账号隔离

个人筛查记录原先对所有账号返回同一份样例（6 条）。不改的话：
新注册账号的首页**永远看不到**「还没有筛查记录」，而它刚做完的筛查也不会出现在列表里
（`submitScreening` 只返回 id，没往数据里写）。现在按 token 里的用户名分开存，
演示账号 `xiaoyu` 仍是数据饱满的样子，新账号从零开始。

> 已知取舍：趋势 / 预警 / 行动计划仍是仓库那套样例，没有跟着清空——
> 真按账号清空的话首页会出现「0 小时」「均值 0.0 h」和大片空白图表，反而更难看，
> 而「连续打卡 12 天」本来就是写死的、清不掉。真实后端下这些字段自然随账号为空。

## 四、跨设备：怎么搬到后端

`src/services/firstRun.ts` 里所有读写都收在两个函数里：

```ts
function readState(username)  { /* localStorage */ }
function writeState(username, next) { /* localStorage */ }
```

搬到后端只需要把它们换成请求（key 从"用户名"换成服务端会话里的用户 id）：

```ts
const readState  = (u) => request.get<FirstRunState>(`/api/personal/first-run`);
const writeState = (u, next) => request.put(`/api/personal/first-run`, next);
```

调用方（LoginPage / WelcomePage / Screening / Dashboard）**一行都不用改**。
建议后端存 `{ status, guide_seen, scale_id, updated_at }` 四个字段。

### 弹窗与流程体感的三处修正（用户反馈）

1. **背景不再虚化**：原来蒙层是 `bg-slate-950/45 + backdrop-blur-sm`，整页被糊成色块，
   盯着很难受。改成纯压暗 `bg-slate-900/35`——弹窗自带边框与投影，层次已经够清楚。
2. **关闭入口只留一个**：右上角 × 与底部「返回当前题」是同一个动作，两个出口反而让人犹豫。
   现在只保留 ×（另有 Esc 与点背景两处兜底），卡片也因此短了一截。
   `.tools/qa/first-run.mjs` 里连"关闭入口数量"一起断言，防止以后再长出第二个。
3. **流程提速**（原来走一遍要等到发困）：
   - 演示数据延迟 `200~800ms` → **`90~240ms`**（四屏连走时每步都等半秒最明显）；
   - 登录后去掉 `setTimeout(500ms)`，直接跳转；
   - 入场动效整体收紧约 40%（卡片落位 760→520ms，量表卡 560~770→320~500ms……），
     页面转场 320→240ms、`.page-enter` 260→200ms；
   - 作答页**选完自动翻页**：一屏一题时原本每题要"点选项 + 点下一题"两次，
     9 题就是 18 击；现在选完即翻，`上一题 / 下一题` 仍保留用于回改。
   - 作答页支持**回车进入下一题**（最后一题上回车即提交，前提是已答完），页脚有提示。
     这里有个坑：焦点在选项按钮上时，浏览器默认把回车当成一次点击，
     会再选一次并再排一次翻页，静默跳掉一题——所以只在真正处理了这次回车时
     `preventDefault()`，另加 450ms 的翻页防重锁（`advanceLock`）。
   实测（无头 Chrome 自动走完，PHQ-9 九题）：**登录 → 主页全程 2.7 秒**，
   其中作答 9 题 2.2 秒、每次 1 击。

### 登录口径：每次登录都进首次流程（用户最终确认）

早期版本按"账号看过引导就不再展示"来跳转。用户确认这不合适：**这个项目的定位是给评委看的作品，
演示时只有一个账号**，按"看过就不再展示"，评委第二次打开就看不到首次引导了——而首次引导正是要展示的流程。
现在的口径：

| 场景 | 行为 |
| --- | --- |
| 打开登录页 | **永远当作没登录过**：表单在、账号密码都留空、不自动放行（点顶栏「登录」必须真的能看到登录框） |
| 登录成功（个人账号） | **一律进 `/personal/welcome`**，不看"是否看过" |
| 登录成功（管理员） | 进管理端，没有引导流程 |
| 「记住我」 | **保留**：勾了 token 存 localStorage，直接访问工作台地址仍是登录态、不用重输；不勾只存 sessionStorage |
| 商用版本 | 把 `entryPath.ts` 里的返回值换回 `needsFirstRunGuide()`（`services/firstRun.ts` 里现成的），一行即可 |

`in_progress` / `done` 这两个状态仍然在记录，用于首页的「继续筛查」与完成态，不再用于登录跳转。

### 修掉"填了东西却没留下"的问题（用户报的）

反馈："我在这里输入了我的感受，可是查看结果好像没有什么变化，而且确认下填表和输入东西的数据也没有当场保留、导入到我的档案。"

查证结果——**他说得对，两头都漏了**：

| 数据 | 之前 | 现在 |
| --- | --- | --- |
| 分数与等级 | ✅ 已落库（档案里能看到） | 不变 |
| **逐题作答** | ❌ `submitScreening` 收下了 `answers` 参数却**没存**（后端接口只回总分，前端也没留） | ✅ 存进记录，档案详情页按题展示"选了什么、几分" |
| **补充记录**（文字/语音/图片） | ❌ 只写进 sessionStorage 草稿，**离开引导就没了**，档案里查不到 | ✅ 02 提交时当场 `saveScreeningSupplement(recordId, …)` 挂到本次记录上，档案详情页新增「本次补充记录」卡 |

顺带让"补充有用"这件事看得见：结果页在**有补充内容时默认落在「分析依据」标签**，
且「本次作答与补充」条目默认展开——否则用户补完回到结果页看不出任何变化，像是白填了。

> 真实后端需要对应接口：`POST /api/personal/screenings/{id}/supplement`（前端已按此约定调用）。
> 逐题答案则走 `submitScreening` 已有的 `answers` 字段，后端落库即可。
