# 个人心理管家

个人端在原有筛查、图谱、聊天和行动计划上建立统一的个人档案。默认关闭，需要本人在首次引导、心理档案或账号设置中开启；聊天、每日问询、行动反馈分别授权。开启历史导入后，既有筛查记录可以参与初始分析。

## 页面入口

心理档案采用同页展示：首屏为“我眼中的你”、近期状态、独立的筛查风险卡片、MBTI偏好及一条优先建议；下方心理建议与知识图谱并列。记忆维护和“筛查历史与原始记录”默认折叠，不作为生成阶段或阅读分析的前置步骤。历史包含文字、语音、图像筛查与各类量表，按类型显示时间、内容摘要、文件名和当次已保存结果，并可查看原始依据；长列表支持展开全部。无文字的媒体也保留历史条目，未保存结果时如实提示，不生成替代结果。模型输出缺少画像时会单独补充生成，并校验引用。

风险只取近30天各类最新的本人筛查结果，不使用MBTI或AI印象定级；缺少有效筛查时展示待评估。MBTI区分本人提供与AI探索性倾向，数据不足时不分配类型；探索性倾向需要不同日期的表达依据，并排除量表单独推断。该功能不是正式MBTI测评，设计参考[MBTI官方的类型核实说明](https://www.myersbriggs.org/unique-features-of-myers-briggs/best-fit-type/)。

- 首页：保持原有布局，不放置心理管家分析卡片。
- 心理筛查分析和首次结果：本次原始结果仍保留，旁边展示同一份近期档案。
- 我的心理档案：近期状态、变化、待确认特点、本人补充、建议、同量表历次结果和原始依据；另有知识图谱视图。
- 建议与行动：接受、调整或暂不采纳建议；接受后进入原有 action_plans，显示“已加入行动计划”，不再展示效果询问与反馈按钮。
- 今日行动计划：使用待办复选框标记完成；保存成功后播放礼花与文字划线，再收起到“已完成计划”。保存失败保持未完成，支持键盘操作、恢复任务及系统减少动态效果设置。
- AI 陪伴：读取统一档案；普通对话及生成进度保存在服务端，刷新后恢复；临时对话不保存消息、不抽取记忆，也不读取长期档案。
- 账号设置：心理管家来源、历史导入、暂停和清空记忆与检索偏好合并为“AI 与分析偏好”卡片，放在设置页底部。该卡片只展示设置，不展示分析概览与跳转链接。清空聊天与清空记忆是不同操作。

## 数据和更新

主业务数据库保存筛查、多模态原始记录、行动计划及效果反馈。新增 `steward_events` 变更日志，通过数据库触发器覆盖新增、修改和删除；无归属的管理端记录不产生个人事件。个人服务以带时间戳的 HMAC 私有接口同步本人记录，版本未变化时不重复传输。首次同步包含历史记录；禁用历史导入时以授权时刻作为起点。原有无时区记录按上海时区解释，内部统一存 UTC，近期范围按上海日期展示。

个人服务使用自己目录下的 SQLite，新增表均以 `steward_` 开头：账号授权、原始证据、记忆、来源排除标记、档案快照、建议、历史迁移标记、聊天生成任务。原始记录与派生认识分开，所有私人记录使用 JWT 的稳定 `sub` 隔离。模型回复、公共案例和 RAG 报告不会作为新的本人证据反复入库。

已有账号在升级后会完整补同步一次多模态元数据，随后继续按变更版本同步；授权范围及排除来源仍然有效。只有文件元数据、没有本人文字内容的记录仅用于历史展示，不进入画像生成或聊天检索。补充文件名不会使已有分析失效。

后台线程池处理持久化更新与聊天任务。主业务同步约每15秒检查一次；界面约每5秒读取状态。任务使用租约，模型失败保留旧快照并在5分钟后重试，也可主动点击更新。开发启动器保证每个目录只有一个所属 Agent，重启时立即恢复未完成租约。多实例生产部署不要开启 `STEWARD_RECOVER_LEASES`，让租约正常到期以免重复生成。

近期状态看近30天，变化要求有不同日期的证据且涉及最近7天；不把不同量表或量表版本的分数混合为趋势。长期特点必须经过本人确认，单次记录或只有量表得分不能产生长期特点候选。跨日期门槛是减少误判的工程限制，不是心理学判定标准。

模型每次最多选择65条证据，并受输入长度预算限制；完整证据仍在库中，界面如实显示本次选择数量。检索采用账号、时间、关键词和确认记忆，未引入新向量数据库。每个生成条目引用真实证据 ID，未知引用会被丢弃，近期观察必须关联近期证据。记录少时明确不足，不自动判为正常。

旧图谱按经主服务核实的用户名读取，只迁移兴趣、关注和已尝试的应对方式，作为无原文依据的待确认线索；旧症状节点不自动转换为当前心理状态。迁移线索在确认前不进入聊天事实上下文。浏览器历史只在用户允许聊天记忆与历史导入后上传，至多200条，仅取本人发言。

Neo4j 中新增 `StewardUser`、`StewardPrivate`、`StewardEvidence`、`StewardMemory`、`StewardDerived` 标签。私人节点包含 user_id，写入幂等投影；记忆、AI观察与建议通过 SUPPORTED_BY 指向证据。现有公共领域图和旧图谱不被破坏。图谱不可用时仍可读取 SQL 档案，后续自动重试投影。

纠正或忘记记忆会排除相关来源，再保存本人纠正内容；不会删除原始筛查。来源排除标记防止同步时重新记回。撤回某类来源会移除相关证据、记忆和当前快照。模型发布前再次检查版本与授权，避免清空后旧任务写回。原始记录删除后在下一轮同步中撤销其依据，失效依据立即从档案上下文中过滤。

## 接口和部署

个人服务公共接口统一位于 `/api/v1/steward`，从登录身份确定本人，管理员角色不能读取这些私人接口：

- `GET /` 档案、授权、版本、任务状态、记忆、建议、量表序列和多模态历史。
- `PUT /settings` 保存来源和历史导入选择；`POST /refresh` 排队更新。
- `GET /evidence?offset=0&ids=...` 分页或按引用查看原始依据；`DELETE /evidence/{id}` 排除来源。
- `POST /memories` 本人补充；`PUT /memories/{id}` 确认、纠正或忘记；`DELETE /memory` 清空并暂停。
- `POST /suggestions/{id}` 接受或暂不需要；接受幂等写入主业务行动计划。
- `GET /graph` 返回与档案一致的个人关联视图。
- `POST /chat/runs` 创建幂等任务；`GET /chat/runs/{id}` 读取增量进度；`POST /chat/runs/{id}/retry` 重试失败任务。
- `GET/DELETE /chat/history` 查看或清空聊天；`POST /chat/import` 获准后导入本机本人发言。
- `POST /safety` 无持久化的原文安全线索检查，不依赖模型可用性。

主服务 `POST /api/personal/steward/feedback` 保存本人的行动效果反馈。私有同步接口 `/api/internal/steward/context`、`/api/internal/steward/plan` 和个人服务 `/api/v1/steward/internal/context` 只接受服务签名，浏览器 JWT 不能使用。主服务的 DeepSeek/Zhipu RAG 在生成时实时读取授权上下文，仅用于解释和建议，不改变统一筛查规则。

使用根目录启动器即可自动生成每目录独立的同步密钥、连接地址和数据库结构；启动器也会检查 Python 源码指纹，更新代码后重新启动时不会复用旧进程。手动部署需配置：

| 服务 | 环境变量 |
|---|---|
| 主业务后端 | `STEWARD_SYNC_SECRET`、`STEWARD_AGENT_URL` |
| 个人 AI 后端 | 同一 `STEWARD_SYNC_SECRET`、`STEWARD_BACKEND_URL`，原有 `LLM_*`、Neo4j 和 JWT 设置 |

服务签名密钥与用户 JWT 密钥用途不同，均不能放进前端构建变量。生产前端沿用 `VITE_PERSONAL_API_BASE`。数据库迁移为增量建表和触发器，不覆盖已有记录。双目录开发保持各自数据库、端口、同步密钥和图谱容器隔离。

主业务后端若部署在 Cloudflare Worker，将同名地址配置为 vars、同步密钥配置为 secret；接口从平台绑定读取配置并使用异步 fetch，个人 AI 服务仍需单独部署。当前验收覆盖本机完整服务及 Worker 适配的隔离测试，未向云端部署。

## 模型调用故障排查

密钥和模型配置正确不代表每个长请求都会在通用等待时间内完成。档案汇总默认使用独立的 `STEWARD_LLM_TIMEOUT=180` 秒和 `STEWARD_MAX_TOKENS=8192` 输出预算；原有聊天 `LLM_TIMEOUT` 保持不变。画像补充生成也使用独立等待时间。服务会分别报告超时、HTTP鉴权/限流/服务错误、空正文、异常响应格式和截断，不再把它们全部显示为“大模型不可用”。日志只记录错误类型与状态码，不记录心理原文、密钥或响应正文。

修改配置或代码后通过项目启动器加载。页面错误可能是上一轮任务的结果，需要重新生成才能验证恢复；若档案版本为0，表示尚未成功生成第一版，原始证据仍然保存。代用户重试真实私人档案会再次调用其配置的模型服务，应先获得明确授权；隔离测试仅使用合成内容。
