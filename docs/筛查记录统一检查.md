# 筛查记录统一检查（2026-11-17）

统一口径：一次已完成的量表，或一次已保存的文字、语音、图像输入，各算一条筛查记录。量表关联的多模态输入仍是独立记录，只展示一次；量表不再被当作文字记录。未完成答卷不计入已完成记录。保留各量表的原始分数及版本，不将不同类型的结果混成一个分数。

## 本次已修改

- `GET /api/personal/records`：按当前账号归属读取全部四类记录，以含时区的提交时间排序；保留量表原始答案、多模态结果与便签。没有沿用旧接口的 100 条截断。
- 个人端“筛查记录”：同一条时间线，提供全部、量表、文字、语音、照片筛选；量表可打开详情、原始作答和已保存的解释；保留多模态记录便签与删除功能。
- 按用户补充要求，量表填写页仅将“我的筛查记录”改名为“量表筛查记录”，保留原有量表列表。
- 首页“最近一次输入”与近期记录统计使用同一份完整来源；统计分别展示量表、文字、语音、图像，不再将量表计为文字，也不遗漏量表所关联的媒体输入。
- 个人端侧栏说明包含四类筛查；首页、复查任务、最近量表卡及旧档案中的量表回看入口转到统一记录页。
- 返回记录页时刷新数据，保留类型筛选；读取失败明确提示，不拼出缺一半的记录列表。

## 检查发现、尚未修改的项

| 位置 | 当前情况 | 后续统一方向 |
| --- | --- | --- |
| 管理端“筛查管理”与多模态记录列表 | `AdminScreening.tsx` / `AdminSupplements.tsx` 仍是分开的列表，前者只读取量表 | 管理端增加全部/类型筛选，合并分页、权限与详情入口；保留独立采集工作流 |
| 管理首页统计与趋势 | `backend/app/handlers/dashboard.py:get_stats` 的总量、本月量、趋势与完成率只查询 `screenings` | 明确区分“全部已完成筛查”和“量表答卷完成率”，纳入 `screening_supplements`，统一时区，避免给完成率换分母后产生误解 |
| 个案累计筛查次数及最后筛查时间 | `case_service.py:sync_personal_case` 的 `screening_count` 与最后时间仅来自量表表；多模态提交不一定更新同一份缓存 | 从两类来源聚合，纳入多模态提交与删除更新；需要兼容没有账号归属的机构录入量表 |
| 旧个人档案 `/personal/cases` | 当前明细分“量表/检索”，量表读取的是短列表，“筛查次数”也只显示量表条数 | 改为读取统一历史，把“检索”类型称为“多模态筛查”，累计次数取两者之和 |
| 检索分析内“我的记录” | 此列表是供再次检索的多模态输入，当前文案容易被理解为全部筛查记录 | 标注为“多模态筛查记录”，增加通往统一记录页的入口；量表仍通过量表证据进入分析，不能将分数字符串冒充媒体内容检索 |
| 个人首页对照版 `/personal/dashboard-v2` | 保留旧版示范展示与局部量表口径，当前主首页未使用 | 若继续保留对照版，应接入同一份记录与活动统计，或明确标注为展示样例 |

心理档案中的“筛查历史与原始记录”已经同时包含量表及多模态来源；其中按来源分类不影响统一概念。但该区域受用户授权来源范围约束，条数可以少于全部原始筛查记录，不应直接当作全系统累计数。

近期综合风险已同时纳入量表和多模态记录；不同量表的分数与多模态线索仍保留其含义，统一记录不等于合并原始分值。
