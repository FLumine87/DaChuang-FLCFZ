# 两个目录同时开发

`D:\DaChuang\DaChuang-FLCFZ` 可以继续使用原启动脚本和默认端口。本目录双击根目录的 `启动项目.bat`，会为本目录启动独立的一套服务。

启动器按目录路径生成默认端口，避开 main 使用的 5173、8000、8001、7474、7687。若端口被其他程序占用，会继续寻找空闲端口。实际地址显示在启动窗口，并保存在本目录 `.local-run/services.json`。浏览器会自动打开正确的前端地址。

- 前端只代理本目录的两个后端；启动器注入运行环境，不改写原 `.env`。
- 每个目录使用自己的 Python 虚拟环境、SQLite 数据库、日志。
- 每个目录拥有独立的 Neo4j 容器和持久化卷，图谱数据从独立的领域种子开始，不会复制或修改 main 的个人图谱。
- 重复启动会核对服务返回的目录、类型和本次进程标识，再决定复用。配置变化会重启对应的本目录服务。
- 任一必要服务或健康检查失败，启动器返回失败，不会把缺失的 Agent 当成完整启动。

在本目录 PowerShell 中使用：

```powershell
.\start_project.ps1                 # 完整启动并打开浏览器
.\start_project.ps1 -NoBrowser      # 完整启动，不打开浏览器
.\start_project.ps1 -Status         # 查看本目录服务状态
.\start_project.ps1 -Stop           # 仅停止本目录服务，保留数据库和图谱卷
.\start_project.ps1 -SkipAgent      # 明确只启动主后端与前端
.\start_project.ps1 -AllowMock      # 明确允许离线模板模式（默认完整启动不允许）
```

后端修改后，执行 `-Stop` 再启动即可加载新代码；前端保留 Vite 热更新。两目录的浏览器地址端口不同，因此登录状态和浏览器本地存储也相互独立。

默认完整启动要求 Agent 关闭 Mock 并配置模型密钥。`personal-backend/.env` 中需设置 `ENABLE_MOCK_ENGINES=False` 和有效的 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`。主后端的报告模型另由 `backend/.env` 中的 `ENABLE_MOCK_ENGINES`、`DEEPSEEK_*` 等配置决定。密钥仅存放在本地被忽略的 `.env` 中，不入库。模型模式为 REAL 表示已配置真实调用；是否能实际返回，还取决于模型服务的网络、额度和可用性。

首次启动需要下载缺少的依赖；可以通过 `PIP_PROXY` 设置 pip 的代理，例如在当前 PowerShell 设置 `$env:PIP_PROXY='http://127.0.0.1:7897'` 后启动。已有可用依赖时不会重复安装。Docker Desktop 是共享的基础设施，请勿在另一目录开发时退出整个 Docker Desktop；停止某个项目应使用该项目的停止命令。

`.local-run/` 包含服务日志和本地容器凭据，已经忽略，不应上传或分享。Neo4j 登录用户名为 `neo4j`，当前目录的密码保存在该目录状态文件的 `graph.password` 字段。

验证命令：`python scripts/test_start_local.py`。完整运行验证还应检查前端页面、主后端健康接口、前端代理到 Agent 的健康接口和 Neo4j 连接状态。
