# 改动：「已缓解」回退（误点保护）

日期：2026-11-07

## 背景

个人端预警只有「标记为跟踪中 / 标记为已缓解」两个动作，手滑点了「已缓解」之后没有任何补救入口。
需求：在「已缓解」旁边加一个低调的胶囊按钮，点一下回退为「跟踪中」（误点保护）。

## 先确认了后端能力

**原本不支持。** `alert_service.update_alert` 的状态机是单向的：

```
pending → processing → resolved → closed
```

个人端从 `resolved` 再发 `tracking`（映射为 `processing`）会被判 409：

```
{"code": 409, "message": "预警状态只能按待处理、处理中、已解决、已关闭顺序流转"}
```

所以本次**给个人端补了一条受控的回退路径**（管理端的状态机不变，仍然只能单向前进）。

## 后端改动

`backend/app/services/alert_service.py`、`mobile-shell/android/app/src/main/python/app/services/alert_service.py`
（两份内容一致，移动端内置后端同步修改）

- `update_alert_by_user` 增加分支：`incoming == "tracking"` 且当前 `resolved` → 调用 `_revert_to_tracking`。
- 回退时：
  - `alerts.status = 'processing'`、`resolved_at = NULL`、`updated_at` 刷新；
  - `follow_up_notes` 追加 `用户自助回退：已缓解 → 跟踪中`；
  - `alert_events` 写一条 `from_status=resolved / to_status=processing` 的审计，
    管理端「处理历史」里能看到是谁、什么时候回退的。
- 只放开个人端这一处；管理员端 `update_alert` 的流转规则保持原样。

## 前端改动

`frontend/src/pages/Alerts.tsx`

- 详情栏底部、绿色「这条预警已缓解…」提示的右侧，出现一个 **胶囊形的小按钮「↺ 回退」**
  （白底、浅灰描边、灰色文字，hover 才稍微加深，不抢视觉）。点击 = 回退为「跟踪中」。
  位置按用户截图确认：放在“已缓解”的确认文案旁边，而不是顶部的状态徽标旁。
- 乐观更新：点完立刻改本地状态，失败回滚并报错（沿用原来的 `handleStatusChange`）。
- 回退成功后的提示从详情里**挪到列表上方的页面级横条**（绿色，可关闭）。
  原因：回退后这条预警往往不再符合当前筛选（比如正筛着「已缓解」），右侧会切到下一条；
  提示如果留在详情里就会跟着换人，甚至滚出视野。

## 验证（本地连真实后端）

- 接口：回退 `PUT /api/personal/warnings/ALT-DEMO12 {"status":"tracking"}` 从 **409 → 200**。
- 审计：`alert_events` 新增 `('processing'→'resolved' 的正常标记)` 与
  `('resolved'→'processing', note='用户自助回退：已缓解 → 跟踪中')` 成对记录。
- 页面：在「已缓解」筛选下点回退 → 统计「已缓解 10 → 9、跟踪中 3 → 4」、
  列表条数 10 → 9、上方出现「已回退为跟踪中」横条、右侧自动切到下一条；console 无报错。
- `tsc -b`、`eslint`、`vite build` 通过。

- 截图里那个 `soaringdragon.github.io` 是**旧的部署构建**（且处于离线演示），
