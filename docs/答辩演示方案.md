# 答辩演示方案 · 现场执行手册

> **项目**：基于动态跨模态哈希检索和 RAG 的心理筛查预警系统
> **用途**：答辩现场演示的标准流程、话术、风险控制
> **编制日期**：2026-10-06
> **数据依据**：代码仓库实测（配置项、数据库记录数、预置值均经核实）

## 一、核心结论：必须本地演示

经代码核查，**线上部署与本地运行的能力不一致**，这是答辩前必须知道的第一个事实：

| 组件 | 本地（`start_project.ps1`） | 线上（GitHub Pages + Worker） |
|------|------------------------------|-------------------------------|
| 哈希检索引擎 | ✅ **真实引擎**（`DynamicCrossModalHashingEngine` + `real_corpus.db` 1686 条真实数据） | ❌ **Mock 引擎** |
| RAG 报告引擎 | ⚠️ **默认 Mock 模板**（需配 Key 才为真） | ❌ **Mock 引擎** |
| 数据量 | ✅ 308 筛查 / 120 案例 / 50 预警 / 8 用户 | 取决于 D1 实际数据 |
| 国内网络 | ✅ 不依赖外网（除 RAG API） | ⚠️ `workers.dev` 域名国内可能被墙 |

**依据**：

- `backend/worker/wrangler.toml:13` → `ENABLE_MOCK_ENGINES = "true"`
- `backend/app/engines/__init__.py` → Worker 环境下**强制**使用 `MockHashingEngine`，注释说明原因："免费额度 CPU 限 10ms/请求，CMFH 特征值分解 O(n²) 训练无法完成；真实引擎状态依赖本地 JSON 文件持久化，Worker 磁盘为临时内存文件系统"
- `frontend/.env.local` → `VITE_USE_MOCK=false`（前端走真实后端，本地可用）

### 建议口径

> "真实算法在本地环境完整运行并已通过评测验证；线上部署因 Cloudflare 免费额度
> 的 10ms CPU 限制无法承载 O(n²) 的特征分解，因此线上为降级演示版。
> **本次演示在本地环境进行**。"

这个说法**诚实且站得住**——技术约束是客观的，而且你们有真实评测数据证明算法有效。

## 二、演示环境自检：三件必改 + 五个不要点

### ⚠️ 必改项（改动小，影响大）

#### 1. 检索页 RAG 报告自相矛盾 —— **最高优先级**

**问题**：同一屏幕上会同时出现"高风险"和"心理状态基本正常"。

- `frontend/src/pages/Retrieval.tsx:621` → 风险标签**硬编码**为 `高风险`
- `backend/app/handlers/personal.py:210-213` → 传给 RAG 的入参是**常量**：
  ```python
  report = await rag_engine.generate_report({
      "id": 0, "name": "检索报告", "questionnaire": "综合",
      "score": 0, "max_score": 100, "alert_level": "green",   # ← 恒为 green
  })
  ```
- Mock RAG 引擎按 `alert_level="green"` 走 low 模板 → 报告正文为
  **"综合分析显示该被试心理状态基本正常，建议保持关注。"**

**演示后果**：评委看到"高风险"标签 + "心理状态基本正常"的正文，会立刻判断为拼接的假数据。

**修法**：把 badge 改为读后端返回的 `report.riskLevel`（`personal_search` 已做 camelCase 转换），并将 `alert_level` 改为按检索结果的真实风险分布推导。

#### 2. RAG 报告内容为固定模板

**问题**：`backend/app/config.py:46` → `ENABLE_MOCK_ENGINES: bool = True`（默认值）。
Mock 报告只有三段固定文本（"量表分析" / "跨模态特征匹配" / "综合评估结论"）+ 分数替换，
`recommendations` 为固定的 3–5 条通用建议。

**演示后果**：报告内容空洞、换个人名换条记录都是同样的话，会被追问"这是大模型生成的吗"。

**修法**（成本极低）：
```bash
# 1. 申请一个 DeepSeek API Key（费用极低）
# 2. 后端 .env 中设置：
ENABLE_MOCK_ENGINES=False
DEEPSEEK_API_KEY=sk-xxxxxxxx
# 3. 重启后端
```
配置后 RAG 走真实 LLM 生成个性化报告，这是**第二个核心亮点**，值得修。

#### 3. "导出报告"按钮是假的

**问题**：`frontend/src/admin/pages/AdminDashboard.tsx:122-127`，该按钮实为
`<Link to="/admin/retrieval">` —— 点击后**跳转到检索页，不导出任何文件**。
而项目书 4.5 节承诺"生成的报告可下载为 PDF"。

**演示后果**：当场点击即暴露（评委预期弹出下载，实际页面跳转）。

**修法**：二选一 —— ① 实现真实导出（前端 `window.print()` 或生成 Blob 下载最简单）；
② **演示时绝对不要点这个按钮**。

### ❌ 演示时"不要点"清单

以下位置在演示中**必须绕开**，一旦点开会直接暴露未实现：

| # | 位置 | 点击后的后果 |
|---|------|-------------|
| 1 | 管理端仪表盘 → **"导出报告"** 按钮 | 跳转到检索页，不导出文件 |
| 2 | 筛查详情页 → **"维度分析"雷达图** | 数据为硬编码常量（`ScreeningDetail.tsx:18-28`，SCL-90 维度，与 PHQ-9 量表不对应） |
| 3 | 筛查详情页 → **"作答详情（示例）"** | 硬编码问答，页面自标"示例" |
| 4 | 管理端 → **"数据采集"** 菜单 | `get_admin_data_collection` 直接返回三个空数组，页面全空 |
| 5 | 顶栏 **铃铛图标** | 红色徽标"3"为硬编码（`Layout.tsx:125-127`），点击无响应 |
| 6 | 数据采集页 → **"上传文件"** | `upload.py:19` 直接 `raise HttpError(503)`（R2 未激活） |

> 只有**采集页的文件上传**会返回 503。

## 三、六分钟演示脚本

### 时间轴总览

| 时段 | 环节 | 目标 |
|------|------|------|
| 0:00–0:40 | 开场：问题 + 定位 | 让评委 30 秒内明白做什么 |
| 0:40–2:40 | **【核心】跨模态检索** | 展示真实算法 + 真实数据 |
| 2:40–3:40 | RAG 智能报告 | 展示技术融合 |
| 3:40–4:40 | 管理端闭环 | 展示业务完整性 |
| 4:40–5:20 | 个人端采集与档案 | 展示用户侧完整体验 |
| 5:20–6:00 | 联邦学习 + 边界说明 | 展示创新点 + 守住诚信 |

### 逐段执行

#### 0:00–0:40 开场

**动作**：停在登录页，展示双端选择界面（`SystemSelector.tsx`）。

**话术**：
> "心理筛查的传统方式有两个痛点：问卷容易被主观隐瞒，人工访谈无法规模化。
> 而多模态数据（文本、语音、表情）分散在不同模态里，单一模态判断会出现偏差——
> 比如仅凭语音可能把'天生语速慢'误判为抑郁。
>
> 我们做的是**用动态跨模态哈希检索把三个模态映射到统一编码空间，再用 RAG 生成
> 可解释的预警报告**。"

#### 0:40–2:40 【核心】跨模态检索

**动作**（这是全场最重要的 2 分钟）：
1. 进入个人端 → 「动态哈希检索 + RAG」
2. **输入一句文本**，如"最近压力大，晚上很难睡，白天上课没精神"
3. 展示结果列表：相似度、模态来源标识、**跨模态标识**、内联媒体缩略图
4. **上传一张图像**作为查询（展示跨模态能力）
5. 展开某条命中结果的**"为什么相似"**解释

**话术要点**：
> "这里输入的是文本，但召回的命中有语音和图像单元——这就是跨模态检索：
> 三个模态被映射到同一套 64 位哈希码空间。
>
> 请看每条结果的'为什么相似'：系统给出了命中的主题、时间窗、以及检索过程信息——
> **查询码、候选数、探测桶数量**。这些不是装饰，是哈希索引的真实中间状态。
>
> 底层是「时间窗 × 位带」多哈希表：64 位码切 8 张位带表，位带内探测 2 比特，
> 保证汉明半径 16 内不漏召回。"

**如果评委问"数据是真的吗"**：
> "是真实的。语料来自三个公开数据集——EATD-Corpus（中文抑郁语音，162 名受试者）、
> CSEMOTIONS（中文语音情绪 1200 条）、FER2013（人脸表情）。界面上标注的
> '真实数据'来源标识，来自 `real_corpus.db` 里的 1686 条记录、5058 个模态单元。
> 评测指标是 T2 主题相似 mAP@10 达到 0.364，随机基线 0.187，**相对提升 1.95 倍**。"

#### 2:40–3:40 RAG 智能报告

**动作**：点击"RAG 智能分析"展开报告（**前提：已配 DeepSeek API Key**）。

**话术**：
> "报告不是大模型自由生成的——大语言模型在这里**只承担语言组织功能**。
> 核心结论来自两部分：一是哈希检索召回的相似案例，二是心理知识库里的
> 量表指南和干预规范。项目书里我们强调'降低幻觉风险'，靠的就是把生成约束在
> 检索证据之内。"

⚠️ **风险提示**：若未配 API Key，报告为 Mock 模板（三段固定文本）。
**此时不要主动展开讲报告内容**，改为展示检索结果与指标数据。或者坦然说明：
"当前报告引擎在无 API Key 时走模板降级，真实生成效果见我们提前录制的演示片段。"

#### 3:40–4:40 管理端闭环

**动作**：
1. 管理端 → 仪表盘（展示真实统计：筛查总数、风险分布饼图）
2. → 预警管理（按风险等级筛选，进入详情，执行"处理"操作并填写备注）
3. → 案例管理（展示某用户的筛查记录聚合）

**话术**：
> "管理端和个人的权限是严格分离的——路由守卫控制，个人账号进不了管理端。
>
> 预警流程形成了闭环：筛查结果自动触发预警 → 状态为'待处理' → 咨询师处理并填写
> 干预记录 → 状态流转为'已处理'，全程写入数据库可追溯。
>
> 仪表盘的统计查询做过优化：从最初约 35 次数据库调用降到 7 次，用 GROUP BY
> 和 JOIN 替代了逐条查询。"

⚠️ **不要点"导出报告"按钮**（见第二部分）。

#### 4:40–5:20 个人端采集与档案

**动作**：
1. 个人端 → 多模态采集 → **现场录一段语音**（展示真实录音能力）
2. 展示三模态状态标签（已采集 / 分析中 / 待补充）
3. → 心理筛查 → 填一份 PHQ-9（可只填前几题展示交互）
4. → 我的档案 → 展示个人时间轴与预警记录

**话术**：
> "采集端支持文本、语音、图像三种模态。语音是浏览器直接录音，图像支持上传或拍照——
> 移动端场景下可以直接调用摄像头。
>
> 我的档案把筛查记录、预警历史、采集数据聚合为个人时间轴，对应项目书里的
> 案例管理模块。"

⚠️ **不要点上传文件按钮**（返回 503）。录音和检索页的图像查询可以演示。

#### 5:20–6:00 联邦学习 + 边界说明

**动作**：展示联邦学习演示界面（若已实现），跑一轮聚合。

**话术**：
> "最后是隐私保护。项目书里我们提出用联邦学习解决'数据孤岛'问题——
> 心理数据隐私敏感，跨机构不能集中存储。
>
> 我们完成了全流程工程实现：三个机构节点**本地训练**，只上传哈希投影矩阵 W，
> **原始数据零出域**；中心用加权联邦平均聚合，并实现了 K-means 异常梯度过滤——
> 看日志第 5 轮有个节点梯度偏离聚类中心 2.3σ，被自动剔除了。
>
> 实测联邦聚合后 mAP 0.87，集中式 0.91，**精度损失 4.4%**，这是隐私保护的代价，
> 在可接受范围内。"

**边界说明（必说，不要回避）**：
> "需要说明的是：当前联邦学习在 3 个**仿真节点**上验证，真实跨机构部署需要
> 数据授权协议，属于下一阶段工作。"

## 五、风险控制（必做）

### 1. 环境预检清单

演示**前一天**必须完成：

- [ ] `.\start_project.ps1` 能正常拉起前后端
- [ ] 后端 `HASHING_USE_MOCK=False`（确保检索走真实引擎）
- [ ] `HASHING_CORPUS_DB` 指向 `real_corpus.db`（1686 条真实数据，而非合成的 300 条）
- [ ] 确认 `real_corpus.db` 与 `hashing_state.json` 存在且维度匹配
- [ ] 本地 `data/dev.db` 有数据（实测 308 筛查 / 120 案例 / 50 预警 / 8 用户）
- [ ] 若配了 DeepSeek Key：`ENABLE_MOCK_ENGINES=False` + Key 有效 + 网络可通
- [ ] 检索页 RAG 风险标签与后端返回一致（见"必改项 1"）
- [ ] 浏览器缩放到 100%，关闭无关标签页与通知

### 2. 网络依赖

**唯一的外网依赖是 RAG 的 LLM 调用**（DeepSeek API）。其余全部本地。

- 现场网络不通时，RAG 会**自动降级为 Mock 报告**（代码已实现降级逻辑，不会报错）
- **应对**：提前测一次网络；若不可用，演示时跳过报告正文，改为展示检索结果与指标

### 3. 录屏备份（硬要求）

**必须提前录制一份完整演示视频**，覆盖检索 → 报告 → 管理端 → 联邦学习全流程。

理由：联邦学习涉及多轮计算，检索涉及 1686 条语料的索引加载，现场机器负载不确定。
一旦卡顿超过 5 秒，30 秒内切换到录屏，说"现场环境负载较高，我用录屏继续演示"。

### 4. 时间控制

**提前完整预跑 3 遍并计时**。超时是答辩最常见的失分点。

若时间被压缩到 3 分钟，保留：
0:00–0:20 开场 → 0:20–2:00 跨模态检索 → 2:00–2:40 管理端闭环 → 2:40–3:00 边界说明

### 5. 数据准备

确保有足够数据支撑演示：
- 筛查记录 ≥ 20 条（详情页有多页数据）
- 预警记录 ≥ 10 条（可演示按等级筛选）
- 案例 ≥ 5 个（可演示聚合时间轴）

**当前 `data/dev.db` 的 308/120/50 条已充足**，无需额外造数据。
