| # | 位置 | 改前 | 改后 |
|---|---|---|---|
| 1 | 顶栏左侧 | `个人端 ｜ 个人首页`（死文字） | `我的空间 › 个人首页`（可点，二级页自动延长） |

| 3 | 页头标题 | `早上好，xiaoyu`（问候） | `今天，想说说自己吗？`（这一页的场景标题）+ 一句说明 |
| 4 | 页头说明的断行 | 断在「三 / 种线索」中间 | 在句号处换行（30 字 / 22 字两行均衡） |

连带的两处小调整：

- 去掉 hero 区里重复的标题与说明（已上移到页头），首屏不再"同一句话说两遍"
- 页脚「原型样张 · …」那行脚注在样张里隐藏（建议以后用 `#source` 参数控制，默认不显示）

### 关于第 4 项（断行）

原因：`.pagehead__desc` 的 `max-width: 58ch` 约合 36 个汉字一行，而这句话 44 字，正好卡在「三种」中间。
试过的四种处理见 `_lede-compare.png`：

| 方案 | 结果 |
|---|---|
| ① 现状 | 断在「三 / 种线索」—— 断在词里，不要 |
| ② **句号处换行（采用）** | 30 字 / 22 字两行，均衡，断点落在句子边界 |
| ③ 收短成一行 | 一行说完，但要丢掉"而不是只看一份量表"这半句 |
| ④ 只把容器加宽到 76ch | **没解决** —— 断点只是从「三种」挪到「只看」中间，还是断在词里 |

结论：光加宽容器治不了中文的词中折行，只有在句子边界控制断点。

### 关于第 5 项（眉标字号）

问题不只是"小"：**13px + 600 字重 + 0.06em 字距 + 高饱和主色蓝**，四条叠在一起就成了"标签"，
不像一句问候；而且中文拉开字距是英文小标题的做法。对比见 `_eyebrow-compare.png`：

| 方案 | 结果 |
|---|---|
| ① 现状 | 13px / 600 / 0.06em / 主色蓝 —— 像标签 |
| ② **推荐（采用）** | 15px / 500 / 0.02em / 次要色 —— 是一行信息，H1 重新当主角 |
| ③ 同 ② 但保留主色蓝 | 也可以，但蓝色会把注意力从 H1 上引走 |
| ④ 问候升到 17px、日期移到页头右侧 | 问候够大了，但日期被甩到最右边，跟内容脱节 |

采用 ② 并加了一档：问候用 `--txt-2`、日期用 `--txt-3`，让中间的「·」有分工。
对应 CSS 写在 `home-a.html` 的局部 style 里（`.pagehead__eyebrow` / `.pagehead__date`），
要落到正式页面时，`prototype/assets/shell.css` 的 `.pagehead` 下加这两条即可。

#### 追记：只改字号不够，深色下会塌成两级

第一版把颜色也一并去掉了，结果**眉标和下面的说明行同色**（都是 `--txt-2`）。实测像素：

| 行 | 改前（全灰） | 改后（采用） |
|---|---|---|
| 眉标 · 问候 | `#d5d2cc`（--txt-2） | `#7592ff`（--accent） |
| 眉标 · 日期 | `#9d9a94`（--txt-3） | `#9d9a94`（--txt-3） |
| H1 | `#faf9f7`（--txt-1） | `#faf9f7`（--txt-1） |
| 说明行 | `#d5d2cc`（--txt-2）← 与问候撞色 | `#d5d2cc`（--txt-2） |

对比见 `_eyebrow-dark-compare.png`。**结论（建议写进 HANDOFF）：深色模式下字重与亮度的差异会被压扁，
层级不能只靠"灰的深浅"来分，眉标这类"需要独立成层"的元素必须带一点品牌色。**

## home-b：大气版首屏（页头与行动区合并）

「不大气」的根子不是字号，是**碎**：原来首屏是一个带边框的 hero 盒子，里面又套 3 个带边框的小卡 + 1 个按钮，
加上整页 1px 描边，看起来就是"盒子里套盒子"。腾讯云的 hero 之所以大气，是因为它是**一整块区域**：
大标题 + 一句副标题 + 一个大按钮 + 大量留白，没有套娃。

`home-b.html` 的做法：

| 项 | home-a | home-b |
|---|---|---|
| 结构 | 页头（标题+说明）+ hero 盒子（3 张入口卡 + 按钮） | **合并成一整块**，无边框 |
| 标题 | 30px | **40px** |
| 内距 | 16 / 20px | **56px 上下、48px 左右** |
| 主按钮 | 32px 高 | **48px 高、左右 30px** |
| 三模态入口 | 3 张带边框的卡 | **一行轻链接**（写一段话 · 录一段语音 · 上传一张图），hover 才变色 |
| 与下方间距 | 12px | **32px** |

另外顺手修了断行：说明那句原本断在「约 / 2–3 分钟」中间，改成在句号处换行。

**还没解决的**：首屏大气了，但下面那一片仍然是碎的 —— 8 张等宽描边卡片、卡间距 12px、卡片标题 17px。
要整页都"舒服"，下一轮要放松下半页的密度：卡间距加大、去掉一部分描边、每屏少放两块。

## home-c：首屏不用卡片容器（当前推荐）

按反馈改的三点：

1. **标题块不再套卡片**：去掉 hero 的背景块、描边、圆角，眉标 + 40px 标题 + 说明直接落在页面背景上。
2. **三个模态入口变成主行动**：原来是「3 张入口卡 + 一个『开始记录』按钮」四个入口说同一件事；
   现在三个入口本身就是主行动（填充式面板、无描边），不再另设按钮 —— 这样"多模态"这个重点一眼看得见。
3. **间距收窄**：页头到入口 28px、入口到内容区 32px（腾讯云那两块之间是 100px+，我们不学）。

另外把**卡片标题从 17px 提到 20px**。理由见下。

| 位置 | 字号 |
|---|---|
| 首屏标题「今天，想说说自己吗？」 | 40px |
| 区块/卡片标题「当前综合状态」等 | 17px → **20px** |
| 正文 / 说明 | 14–15px |

### 关于"腾讯云的标题做了区分"

实测腾讯云那两张图的字高（同一张截图内）：

| | 字高 | 换算字号 | 比值 |
|---|---|---|---|
| 腾讯云开发者（页面标题） | 65px | ≈43px | **1.5** |
| 开发者生态（区块标题） | 43px | ≈29px | |

腾讯云是 **三级**：页面标题（43）→ 区块标题（29）→ 卡片内容。
我们现在只有 **两级**：页面标题（40）→ 卡片标题（17，太接近正文 14）。
所以先把卡片标题提到 20px；要真正对齐腾讯云的节奏，下一步应该给下半页**分区块**（如「今天」「最近状态」「需要关注」），
每个区块一个 29px 左右的标题，卡片再收进区块里 —— 这样页面才有层级，不再是 8 张等权卡片平铺。

### 间距与字号（2026-10-14 第二轮调整）

**三级字号**（实测渲染图上的字高，÷2 得字号）：

| 行 | 字号 | 2x 字高 |
|---|---|---|
| 第 1 行 下午好，xiaoyu · 3 月 20 日 星期五 | **20px** | 39px |
| 第 2 行 今天，想说说自己吗？ | **40px** | 79px |
| 第 3 行 说明 | **15px** | 28px |

即 15 < 20 < 40，眉标比说明大、比标题小。

**间距**：

| 位置 | 改前 | 改后 |
|---|---|---|
| 标题块 → 三个入口 | 28px | **44px** |
| 三个入口 → 「上次记录」 | 20px | **16px** |
| 首屏 → 下方内容区 | 12px | **48px** |
| 眉标 → 标题 | 6px | 14px |
| 标题 → 说明 | 10px | 16px |

**顺带修的**：三个入口的标题原本继承了全局 `a { color: var(--accent) }`，三个都变蓝；
现在改成 `--txt-1`（白），蓝色只留给眉标里的问候和入口图标，避免首页的颜色预算被抢走。

## home-d：抗锯齿修正 + 悬挂眉标（当前推荐）

### 1. 「小字不锐利」的根因找到了

不是错觉，是设置问题：

| 位置 | 设置 | 结果 |
|---|---|---|
| `prototype/assets/base.css:40` | `-webkit-font-smoothing: antialiased` | 灰度抗锯齿，**笔画变细、发糊** |
| `frontend/src/index.css:162-167` | `auto` | 系统次像素抗锯齿，中文小字明显更锐利 |

React 那边已经改过来了，而且注释里写明了原因（"它会把 macOS 的次像素抗锯齿换成灰度抗锯齿，笔画变细、观感发糊。
腾讯官网保持系统默认（auto），中文小字明显更锐利"）；**原型的 base.css 没跟上**，
样张是从原型复制的，所以继承了这个"糊"的设置。

实测同一段说明文字的墨量（像素亮度求和，越高越实）：

| 设置 | 墨量 |
|---|---|
| `antialiased` | 582,108 |
| `auto` | **765,956（+31%）** |

对比图见 `_aa-compare.png`（上=antialiased，下=auto）。

> **建议直接修 `prototype/assets/base.css:40`**：一行改动，16 个原型页面的中文小字一起变实。

### 2. 文字的起点做出层次

三个方案见 `_layer-compare.png`：

| 方案 | 做法 |
|---|---|
| ① 全部顶格 | 现在这样，三行同一个左边界 |
| ② **悬挂眉标（采用）** | 眉标顶格，**标题与说明一起缩进 34px**，眉标像挂在页边 |
| ③ 阶梯 | 眉标与标题顶格，只有说明缩进 34px —— 看着像对齐失误 |

采用 ②。注意它带来的取舍：标题块相对下面的卡片区向右缩了 34px，
换来的是"页头"和"内容"两段的分界更清楚。

## home-e：下半页洗牌（当前推荐）

按「首页只回答三个问题」重排，7 块 → 3 块 + 1 条常驻。

| 现在的块 | 处理 |
|---|---|
| 首屏三个模态入口 | **收成一个主按钮** + 一行旁注「文字 · 语音 · 图像，任选或都做」 |
| 当前综合状态（51/100 + 三条信号条 + 量表行 + 两个按钮） | 拆掉：趋势与维度 → 「你的最近」；信号条 → 记录详情页；量表 → 我的档案 |
| 这次结论用到了什么（三模态证据 + 完整度） | 移到记录详情页 |
| 问问分析助手 | 后端没有对话能力（无会话/无流式/模型是 mock），先撤出首页 |
| 最近预警 | 改成「需要你处理」，**有预警才出现** |
| 今天先做这些 | 保留 → 「今天可以做的」 |
| 需要有人陪你聊聊吗 | 收成**底部常驻条** |
| 辅助量表（折叠） | 移到我的档案 |

### 新增：两个原来首页没有的东西

1. **「你的最近」做厚** —— 一句话结论（24px）+ 三个**生活维度**（情绪 / 睡眠 / 压力），
   每行 = 迷你折线 + 当前值 + 环比方向。
   关键改动：把「文字 / 语音 / 图像 三条信号条」换成生活维度 —— 那是**模态贡献度（给我们看的）**，
   情绪/睡眠/压力才是**用户能对上号的**。数据 `mockData.ts` 的 `moodTrend` 里本来就有这三条序列。
2. **最近记录时间线** —— 补上「我的过去」，这是原来首页完全缺失的一块。

### 数据口径（避开评审意见 1）

只在**有真实单位**的地方露数字：睡眠用「6.1 小时」；情绪与压力用等级词（波动/偏高）+ 环比方向，
不露裸分 —— 否则又会撞上「这个分数指的是什么，没有单位」。

### 一个坑（踩过了，记下来）

新写的 `.dim`（指标行）**和原型已有的 `.dim` 工具类重名**，导致预警块里那行日期也套上了网格样式、挤成一条。
已改名为 `.mrow`。**在 prototype 的页面里加组件，类名前先 grep 一下是否已被占用。**

### 修订：「上次记录：今天 08:20 · 已连续记录 12 天」为什么奇怪

两个原因：

1. **它跟首屏的按钮打架**：标题问"今天，想说说自己吗？"、按钮写"记录一下现在"，
   旁边一行却说"上次记录：今天 08:20" —— 今天已经记过了，那这个按钮是让我再记一次吗？
2. **它是"数据"不是"信息"**：08:20 这个时间点对用户没意义；"连续 12 天"还是写死的演示值。

改法：

| 原 | 改 |
|---|---|
| 按钮旁放「文字 · 语音 · 图像，任选或都做」 | 按钮旁改成**今天的记录状态**「今天 08:20 记过一次」 |
| 模态说明靠旁注 | 归回说明行「写几句、说一段、或者拍一张都可以。系统会把三种线索一起看。」 |
| 孤立一行「上次记录…已连续记录 12 天」 | 删除；「已连续记录 12 天」挪进「你的最近」的眉标行 |

**更根本的一点**：这行暴露出首页缺一个**「今天打卡了没有」的状态**。
健康类产品每天打开的第一眼就该看到这个状态，而不是永远显示同一个 CTA。
建议两种状态两套文案：

- 今天还没记 → `[ 记录一下现在 ]  今天还没有记录`
- 今天记过了 → `[ 看看今天记的 ]  今天 08:20 记过一次`

## home-f：首屏加「评估心理状态」+ 一行状态

### 为什么加

量表降级之后被挪进「我的档案」，等于藏起来了。但 4 份量表是后端 `questionnaires` 表里**唯一有真实数据**的部分，
也是临床上唯一有据可依的部分。完全藏起来既不诚实，也少一块可讲的东西。

「记录」和「评估」是两件不同的事，可以并列，**但不能做成两个平级实心按钮**（那又变成两个入口说同一件事）：

- **记录**（每天）：三模态、无结构、看趋势 → 实心主按钮
- **评估**（每 2 周）：量表、有结构、看刻度 → 描边次按钮

### 三种状态（`_assess-states.png`）

| 状态 | 按钮 | 下面那行字 |
|---|---|---|
| ① 从没做过 | 品牌色描边 | 「还没做过评估 · 约 3 分钟」（`--txt-2`，邀请） |
| ② 做过，还没到期 | 中性描边 | 「上次评估 3 月 4 日 · 9 分（轻度）· 建议每 2 周一次」（`--txt-3`，只陈述） |
| ③ 到期了 | 品牌色描边 | 「距上次评估 16 天，可以做一次了」（品牌色，提醒） |

**原则：只有"该做"的时候才强调，其余时候只陈述、不催。**
心理健康产品天天催"你该评估了"会制造焦虑 —— 而且 PHQ-9 的回忆期本来就是"过去两周"，
"每 2 周一次"是有临床依据的节奏，不是我们编的。

「记录一下现在」这一侧全程不变（「今天 08:20 记过一次」）。

## home-h2：浅色页头「单薄」的修正

### 先量了一下，问题不在字号

| | 登录页（`.auth-hero-title`） | 我们的页头 |
|---|---|---|
| 大标题 | 34px | **40px**（比登录页还大） |
| 说明 | 14px × 3 行 | 15px × 2 行 |

**所以"单薄"不是字小，是元素少**：登录页那块左边是「标题 + 说明 + 徽章行 + 链路条 + 卡片」五样，
我们只有三行字。

### 真正的问题是排版规格不一致（这条是硬伤）

`frontend/src/index.css:1344-1357` 写明了登录页/主页的规格与理由：

> 字重 500 + 极轻正字距（+0.01em）：不挤压字面，笔画留白更多，观感更"清新"。
> 原先的 700 + tracking-tight（−0.025em）是"**又粗又挤**"，与清新相反。

而我们的页头用的是 **600 + −0.01em** —— 正好是那边明确否掉的方向。

### 改了三处

| 项 | 改前 | 改后 |
|---|---|---|
| 标题字重 | 600 | **500**（同 `.auth-hero-title`） |
| 标题字距 | −0.01em | **+0.25px** |
| 标题行高 | 1.16 | **1.2** |
| 说明字号 | 15px | **16px** |
| 页头底部 | 无 | **一条 hairline**（浅色下给这块一个"底"，不至于飘在留白里） |
